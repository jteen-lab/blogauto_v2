# 색인 되먹임 + 발행 전 품질 게이트

> 검색 노출이 죽은 상태에서 계속 발행하면 신호가 더 나빠진다. 색인 결과를
> 발행량에 되먹이고, 문제 있는 글은 발행 전에 잡는다.
> 진단: `docs/plans/search_visibility_all_blogs.md`

## 1. 색인률 → 발행량 되먹임

지금은 색인이 0이어도 발행량이 그대로다. 색인 점검 기능은 있는데 그 결과가
발행 결정에 전혀 반영되지 않아, 크롤 수요가 죽은 사이트에 글이 계속 쌓였다.

```mermaid
flowchart TD
    A[생성 요청] --> B[성장 프로파일 단계 결정]
    B --> C[색인률 조회<br/>최근 30일 발행분]
    C --> D{점검된 URL 이 충분한가?<br/>5건 이상}
    D -->|아니오| E[상한 없음<br/>측정 근거 부족 — 막지 않는다]
    D -->|예| F{색인률}
    F -->|30% 이상| G[상한 없음]
    F -->|10~30%| H[일일 발행량 절반]
    F -->|10% 미만| I[하루 1개]
    F -->|0% + 30일 경과| J[생성 중단 + 사유 표시]
    E --> K[최종 발행량 = min 프로파일, 상한]
    G --> K
    H --> K
    I --> K
    J --> L[생성하지 않음]
```

**측정 근거가 없으면 막지 않는다.** 새 블로그는 점검 이력이 없어 색인률이
0으로 보이는데, 그걸로 발행을 멈추면 시작조차 못 한다.

## 2. 발행 전 품질 게이트

```mermaid
flowchart TD
    A[글 생성 완료] --> B{본문 길이}
    B -->|기준 미만| X[보류]
    B -->|충족| C{형제 사이트에 같은 제목?}
    C -->|있음| X
    C -->|없음| D{검증 불가 수치가 글의 핵심?}
    D -->|해당| X
    D -->|아님| E[구조 정리]
    E --> F[H1 중복 제거]
    F --> G[내부링크 유사도 미달분 제외]
    G --> H[발행]
    X --> Y[보류 사유와 함께 목록에 남김<br/>사용자가 확인·재생성]
```

**보류된 글은 조용히 버리지 않는다.** 왜 발행이 안 됐는지 모르면 사용자가
설정을 고칠 수 없다.

## 3. 등록 시 점검

```mermaid
flowchart TD
    A[블로그 연결 테스트] --> B[robots.txt 확인]
    B --> C{사이트맵이 자기 도메인인가?}
    C -->|아니오| W1[경고: 남의 사이트맵을 가리킴]
    C -->|예| D{네이버 소유확인 태그}
    D -->|없음| W2[안내: 네이버 미등록]
    D -->|있음| E[정상]
```

레시피노트의 robots.txt 가 수작남 사이트맵을 가리키고 있었다. 등록 시점에
드러났으면 몇 주를 허비하지 않았다.

## 설계 원칙

- **막을 때는 이유를 남긴다.** 발행이 조용히 멈추면 고장과 구분되지 않는다.
- **근거 없이 막지 않는다.** 측정 표본이 적으면 상한을 걸지 않는다.
- **자동으로 되돌린다.** 색인률이 회복되면 발행량도 스스로 돌아온다.
