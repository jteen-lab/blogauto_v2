# 운영 가이드 — 블로그 할당·테스트·조정

> **용도**: 모듈 카탈로그를 만든 뒤 실제 블로그에 할당하고, 글 결과를 확인해 점진 확장·조정하는 절차.
>
> **마지막 갱신**: 2026-05-27

---

## 1. 블로그 → 모듈 할당 규칙

### 원칙
- 한 블로그 = 1개 카테고리 그룹 = 1개 모듈
- 같은 카테고리라도 블로그마다 다른 모듈을 쓰면 결과 다양성 ↑
- 모듈은 카테고리에 고정돼 있으므로 카테고리가 일치하는 모듈 중에서만 선택 가능

### 분배 방식 3가지

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **수동 매핑** | 블로그마다 운영자가 직접 모듈 선택 | 통제 명확 | 블로그 많을수록 부담 |
| **홀짝 분배** | 블로그 ID 홀수 → 모듈 A, 짝수 → 모듈 B | 자동·균등 | 변주가 2개로 제한 |
| **ID 해시 분배** | `blog_id % 변주개수` 로 선택 | 자동, N개 변주 지원 | 균등 분배 보장 X (해시 분포 의존) |

**권장**: 블로그 30개 이하 → 수동 매핑, 30개 초과 → 홀짝 또는 ID 해시.

### 분배 예시 (블로그 100개)

```
카테고리 [AI · IT] 블로그 20개
  → 모듈 1 (S1_AI_Expert_P1) : 블로그 ID 홀수 10개
  → 모듈 2 (S1_AI_Analyst_P4) : 블로그 ID 짝수 10개

카테고리 [여행 · 맛집] 블로그 30개
  → 모듈 12 (S4_TravelEats_Essayist_P5) : ID % 3 == 0  → 10개
  → 모듈 13 (S4_TravelEats_Friend_P5)   : ID % 3 == 1  → 10개
  → (변주 추가 모듈 13b)                  : ID % 3 == 2  → 10개

카테고리 [건강 · 의학] 블로그 15개
  → 모듈 5 (S2_Health_Teacher_P2) : 홀수 8개
  → 모듈 6 (S2_Health_Friend_P3)  : 짝수 7개
...
```

### BlogAuto 에서 할당하는 위치

생성 모듈의 settings 에서 카테고리·블로그 매핑(`blog_category_map`)을 관리한다. 같은 카테고리에 모듈 2~3개가 있다면 운영자가 모듈 페이지에서 어느 블로그를 어느 모듈에 연결할지 선택한다.

## 2. 글 생성 테스트 (모듈 출시 전 검증)

새 모듈을 만들면 **블로그에 대량 할당하기 전 5~10건 테스트 발행** 필수.

### 체크리스트

| 항목 | 확인 방법 | 합격 기준 |
|---|---|---|
| **페르소나 반영** | 글 어말 패턴 확인 (격식체/구어체/회고체 등) | 의도한 종결 어미 80%+ 사용 |
| **독자 수준 반영** | 용어 풀이 여부, 표/목록 깊이 | 입문은 풀이 有, 결정은 비교표 깊음 |
| **섹션 패턴 반영** | 6개 ## 섹션 구조 확인 | 지정한 패턴(P1~P5)의 A~F 역할 일치 |
| **표 위치** | B(2번째), E(5번째) | 표 2개 모두 존재 |
| **목록 위치** | C(3번째), F(6번째) | 목록 2개 모두 존재 |
| **시작 톤 반영** | 첫 문장 확인 | 의도한 톤(수치/공감/장면 등) 명확 |
| **메타 텍스트 누락** | "STEP 1", 구분선(─, ---), 해시태그 검색 | 0건 |
| **마치며 헤딩** | `## 마치며` 존재 | 1개 존재 |
| **글자 수** | 도입 200자+, 각 섹션 250자+, 마치며 200자+ | 모두 만족 |

### 테스트 절차

```
1. 모듈 만들기 (settings 에 카테고리 선택, user_prompt_template 붙여넣기)
2. 해당 카테고리의 미사용 제목 5~10개 확보
3. 한 제목씩 글 생성 (대시보드의 "수동 생성" 또는 "테스트 생성" 기능 사용)
4. 생성된 글을 체크리스트 항목별로 확인
5. 합격률 80% 이상이면 출시 OK, 미달이면 조정 (다음 섹션)
```

---

## 3. 결과 OK 판단 기준

| 합격률 | 판정 | 액션 |
|---|---|---|
| **90% 이상** | 우수 | 즉시 본격 할당 |
| **80~90%** | 양호 | 미달 항목만 모듈 블록 미세 조정 후 재발행 1~2건 확인 후 출시 |
| **60~80%** | 보통 | 페르소나 또는 패턴 블록 중 어느 쪽이 문제인지 파악 후 교체 |
| **60% 미만** | 미흡 | 모듈 자체를 다시 설계 (클러스터 매칭부터 재검토) |

### 항목별 미달 시 우선 점검 포인트

| 미달 항목 | 가장 흔한 원인 | 조정 방법 |
|---|---|---|
| 페르소나 안 맞음 | 어말 가이드가 모호 | 블록의 "어말 종결" 예시 3~5개로 늘리기 |
| 표·목록 누락 | LLM 모델이 가벼움 | 더 큰 모델(예: Claude Opus, GPT-4)로 변경 또는 "반드시" 표현 강화 |
| 섹션 패턴 안 따름 | 패턴 정의가 추상적 | 각 섹션에 한 문장 예시 추가 |
| 메타 텍스트 출력 | "출력 금지" 강도 부족 | 기본 원칙 블록 맨 위로 이동 + 강조 추가 |
| 시작 톤 안 맞음 | 시작 톤이 페르소나와 충돌 | 페르소나에 맞는 톤으로 교체 (`style_catalog.md` 참고) |
| 글자 수 미달 | max_tokens 설정 부족 | Module.settings.content_generation.max_tokens 상향 (4000+ 권장) |

## 4. 점진 확장 절차

```
Phase A. 우선 클러스터 1개 검증 (예: S1)
  └ 모듈 1·2 만들고 5~10건 테스트
  └ OK 면 해당 카테고리 블로그 전체에 할당

Phase B. 나머지 클러스터 1개씩 추가
  └ 한 클러스터 검증되면 다음 클러스터 진행
  └ 클러스터 5개 모두 완료 = 카탈로그 풀세트

Phase C. 변주 추가 (V2/V3)
  └ 각 클러스터 메인 모듈 운영 안정화 후
  └ 같은 클러스터 변주 추가 → 같은 카테고리 블로그 사이 다양성 ↑

Phase D. 운영 데이터 기반 조정
  └ generation_history 데이터 모아 어느 모듈이 잘 작동하는지 분석
  └ 발행 완료율·평균 글자수·재발행 횟수 등 지표로 우열 판단
  └ 약한 모듈은 블록 조정 또는 폐기
```

한 번에 15개 모듈 모두 만들지 않는다. **한 클러스터 안정화 → 다음 클러스터** 순으로 점진.

## 5. 운영 중 발견되는 흔한 이슈와 대응

### 이슈 A: 같은 카테고리인데 글이 너무 비슷
- **원인**: 변주 모듈이 차이가 약함
- **대응**: 페르소나를 같은 클러스터 안에서 바꾸기 (예: 전문가 → 분석가)
- 그래도 비슷하면 섹션 패턴도 함께 변경 (P1 → P4)

### 이슈 B: 카테고리에 안 맞는 어투가 섞임
- **원인**: 모듈이 담당하는 카테고리 범위가 너무 넓음
- **대응**: 카테고리 필터를 좁혀 모듈 분리 (예: "건강·의학·육아" → "건강·의학" 모듈 + "육아" 모듈)

### 이슈 C: 특정 모듈에서만 글이 짧게 나옴
- **원인**: 섹션 패턴의 일부 섹션이 LLM 에 모호하게 전달됨
- **대응**: 해당 섹션에 "최소 280자 이상" 처럼 길이 명시

### 이슈 D: 표·목록이 자주 빠짐
- **원인**: 모델이 가볍거나, "반드시 포함" 강조가 약함
- **대응**: 
  - 모델 업그레이드 (Claude Sonnet 4.6 → Opus 4.7 등)
  - 또는 섹션 약속에 "B 섹션에 표가 없으면 미완성으로 간주" 같은 강한 표현 추가

### 이슈 E: 같은 글이 반복적으로 같은 어휘 사용
- **원인**: 페르소나 블록의 예시 어휘가 너무 적음
- **대응**: 어휘 사전을 페르소나 블록에 추가 (예: "감탄어로 진짜, 솔직히, 완전, 의외로 등 다양하게 사용")

## 6. 향후 시스템 통합 검토 사항 (선택)

지금은 운영자가 수동으로 모듈을 만들고 할당하지만, 향후 다음 자동화 가능:

| 자동화 항목 | 효과 | 구현 부담 |
|---|---|---|
| 모듈 페이지에 "사용 블로그 수 / 권장 분배" 힌트 표시 | 운영자 결정 편함 | 낮음 |
| 블로그 ID 해시 자동 분배 옵션 | 100개+ 블로그 분배 자동 | 낮음 |
| generation_history 기반 모듈별 품질 점수 | 약한 모듈 자동 식별 | 중간 |
| 역설계 도구 (운영자가 우수 글 입력 → 프롬프트 초안 생성) | 새 모듈 작성 시간 단축 | 중간 |

도입은 운영 안정화 후 우선순위 매겨 진행.

## 정리 — 한 페이지 체크리스트

```
□ style_catalog.md 로 카테고리 → 클러스터 매핑 결정
□ style_blocks.md 의 블록을 참고해 V1 템플릿에 끼워넣어 모듈 프롬프트 작성
□ modules.md 카탈로그에서 만들 모듈 우선순위 결정 (한 클러스터부터)
□ BlogAuto 모듈 페이지에서 카테고리 필터 설정 + 프롬프트 붙여넣기
□ 5~10건 테스트 발행
□ 체크리스트로 검증 (80% 이상이면 출시)
□ 블로그 → 모듈 할당 (수동 또는 홀짝/해시)
□ 다음 클러스터로 확장
□ 운영 1~2주 후 데이터 보고 약한 모듈 조정
```
