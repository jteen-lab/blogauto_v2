# 프롬프트 카탈로그 시스템

> **목적**: 블로그 100개 이상 운영 시 "한 사람·한 회사가 쓴 것 같은" 느낌을 없애고, 카테고리에 어울리는 다양한 스타일로 글이 생성되도록 BlogAuto 생성 모듈을 체계적으로 구성한다.

---

## 핵심 아이디어

> **모듈 = (카테고리 필터) + (1 페르소나 + 1 독자수준 + 1 섹션패턴 고정) + (프롬프트)**

- BlogAuto 생성 모듈이 이미 카테고리에 고정되어 있어 프롬프트 내 분기는 불필요.
- 모듈마다 페르소나·독자수준·섹션패턴을 하나씩 고정.
- 같은 카테고리에 변주 모듈 2~3개를 두어 블로그별 차별화 확보.

---

## 문서 구성

| 문서 | 내용 | 누가 보나 |
|---|---|---|
| [`style_catalog.md`](style_catalog.md) | 5클러스터 정의 + 카테고리 매핑 + 권장 조합 | 모듈 설계 시 |
| [`style_blocks.md`](style_blocks.md) | 페르소나 5종, 독자수준 3종, 섹션패턴 5종, 시작톤 5종 — 복붙용 블록 | 모듈 프롬프트 작성 시 |
| [`modules.md`](modules.md) | 15개 권장 조합 카탈로그 + 완성 예시 2개 + 변주 만드는 법 | 모듈 만들 때 |
| [`operation.md`](operation.md) | 블로그 할당, 테스트 체크리스트, 결과 판단, 조정 절차 | 출시·운영 시 |

---

## 사용 흐름 (처음 시작하는 경우)

```
1. style_catalog.md
   └ 우리 블로그들이 어느 클러스터에 분포하는지 파악
   └ 운영할 클러스터 우선순위 결정 (전체 5개 한 번에 안 만들고 1~2개부터)

2. modules.md 카탈로그
   └ 만들 모듈 행 선택 (예: 모듈 1, 2)

3. style_blocks.md
   └ 해당 모듈의 페르소나·독자수준·섹션패턴·시작톤 블록 찾기

4. modules.md 완성 예시
   └ 예시 1 또는 2 를 복사 → 4개 블록 자리에 위에서 고른 블록 끼워넣기
   └ 완성된 프롬프트를 BlogAuto 모듈 페이지 user_prompt_template 에 붙여넣기
   └ 모듈 settings 에 카테고리 필터 설정

5. operation.md
   └ 테스트 발행 5~10건
   └ 체크리스트 통과율 80% 이상이면 본격 할당
   └ 미달이면 우선 점검 포인트 따라 조정
```

---

## 운영 규모 가이드

| 운영 블로그 수 | 권장 모듈 수 | 한 클러스터당 변주 |
|---|---|---|
| 10개 이하 | 3~5개 | 1개 (변주 불필요) |
| 10~30개 | 5~8개 | 1~2개 |
| 30~100개 | 10~15개 | 2~3개 |
| 100개 초과 | 15개 이상 | 3개 + 카테고리 세분화 |

## 자주 묻는 질문

**Q. 모듈을 한 번에 15개 다 만들어야 하나요?**
A. 아닙니다. 한 클러스터(2~3개 모듈)부터 시작해 검증 OK 면 다음 클러스터 추가. 점진 확장이 안전합니다.

**Q. 5클러스터 매핑은 프롬프트에 넣어야 하나요?**
A. 아닙니다. 운영자 참고용 외부 메모입니다. 모듈 자체가 카테고리에 고정돼 있어 LLM 은 자기가 어느 클러스터인지 알 필요가 없습니다.

**Q. 같은 카테고리에 모듈 2개를 만들면 어떻게 블로그에 분배되나요?**
A. BlogAuto 모듈 페이지에서 운영자가 직접 블로그를 선택해 연결합니다. 100개 이상이면 홀짝·ID 해시 자동 분배 옵션 도입을 검토합니다 (`operation.md` Phase D 참고).

**Q. 토큰 비용은 얼마나 늘어나나요?**
A. 모듈 1개 프롬프트 ≈ 400~500 토큰. 기존 베이스(~600자)보다 오히려 가볍습니다. 카테고리별 분기 lookup 을 안 넣었기 때문입니다.

**Q. 새 카테고리가 추가되면 어떻게 하나요?**
A. `style_catalog.md` 의 카테고리 매핑에 해당 카테고리를 추가한 뒤, 해당 클러스터의 기존 모듈에 카테고리 필터를 추가하면 됩니다. 새 모듈 만들 필요 없는 경우가 많습니다.
