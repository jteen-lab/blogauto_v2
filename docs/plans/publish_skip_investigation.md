# 발행 건너뜀 반복 — 원인 조사

> 2026-09-01 · 지적: "인포노트와 굿팁꿀팁이 계속 발행을 건너뛴다.
> 성장 프로파일에서 발행 횟수가 충족됐는데 계속 시도한다."
> **조사만 수행. 수정 없음.**

## 결론 요약

문제는 **두 겹**이다.

| # | 문제 | 영향 |
|---|---|---|
| 1 | 「최초 실행」 판정이 스스로를 유지해 10분마다 무한 재시도 | 6개 블로그 |
| 2 | 재고가 있는데 카테고리 불일치로 발행 후보에서 제외 | 3개 블로그 |
| 3 | 발행이 성공했는데도 실패로 기록 | 6개 블로그 |

## 1. 「최초 실행」 무한 루프 — 자기 자신을 유지하는 고리

`flow_scheduler.py` 의 발행 액션은 재고가 없을 때 두 갈래로 나뉜다.

```python
is_first = state and state.successful_executions == 0
if is_first:
    pub_result = {"skip_interval": True, ...}   # 간격 미소비
else:
    pub_result = {"hold": True, ...}            # 간격 소비
```

그리고 후처리에서:

```python
if result.get("skip_interval"):
    state.release_execution_lock()
    # 10분(MIN_CHECK_INTERVAL) 뒤 재체크
    # ← record_execution() 을 부르지 않는다
elif result.get("hold"):
    state.record_execution(True)   # 여기서는 부른다
```

```mermaid
flowchart LR
    A[successful_executions = 0] --> B[is_first = True]
    B --> C[skip_interval]
    C --> D[record_execution 안 부름]
    D --> A
```

**한 번도 성공한 적 없는 발행 액션은 이 고리에서 나올 수 없다.**
재고가 생겨 실제로 발행되기 전까지 10분마다 영원히 시도한다.

### 실측 — 오늘 하루 스킵 횟수

| 블로그 | 오늘 스킵 |
|---|---|
| 굿팁꿀팁 | 30회 |
| 인포노트 | 8회 |
| 슈마즈 | 7회 |

### 해당 블로그 전수 (successful_executions = 0)

| 플로우 | 총 실행 | 연속 실패 | 마지막 실행 |
|---|---|---|---|
| 굿팁꿀팁_워프 | 21 | 21 | 08-31 22:23 |
| 인생꿀팁_워프 | 10 | 10 | 08-31 18:08 |
| 슈마즈_구글블로거 | 4 | 4 | 09-01 11:32 |
| 라이프인포_워프 | 2 | 2 | 08-31 17:28 |
| 레시피노트_블로거 | 2 | 2 | 08-31 19:23 |
| 인포노트_워프 | 2 | 2 | 09-01 13:04 |

## 2. 재고가 있는데 발행 후보가 아니다

굿팁꿀팁은 미발행 재고가 **1건 있는데도** "발행 가능 글 없음" 으로 스킵한다.
실제 사유를 조회하면 이렇다.

```
굿팁꿀팁  재고 1건이 블로그 카테고리에 없는 하위주제라 제외됨
          — 구인구직 사이트(1)
수작남    재고 2건이 … — 문화 정보(1), 월급 관리(1)
잡학다식  재고 1건이 … — 고객센터·연락처(1)
```

**사유는 이미 코드가 알고 있는데 화면에 안 보인다.** `describe_publish_block()`
은 `hold` 경로에서만 호출된다. 「최초 실행」이면 `skip_interval` 을 타므로
사용자는 "발행 가능 글 없음" 이라는 뭉뚱그린 문구만 본다.

굿팁꿀팁이 30번 스킵하는 동안 진짜 이유(카테고리 불일치)는 한 번도
로그에 남지 않았다.

### 전 블로그 발행 후보 현황

| 블로그 | 후보 | 사유 |
|---|---|---|
| 꿀팁대백과사전 · 레시피노트 · 머니조아 · 인생꿀팁 | ⭕ | — |
| 굿팁꿀팁 | ❌ | 구인구직 사이트(1) 카테고리 불일치 |
| 수작남 | ❌ | 문화 정보(1) · 월급 관리(1) |
| 잡학다식 | ❌ | 고객센터·연락처(1) |
| 군타 · 라이프인포 · 슈마즈 · 인포노트 · 취업인포마스터 | ❌ | 재고 자체가 없음 |

> 카테고리 불일치 3건 중 2건(「구인구직 사이트」, 「고객센터·연락처」)은
> 품질 게이트가 위험 유형으로 잡는 주제다. 니치를 좁히면서 카테고리에서
> 뺐는데 그때 만들어 둔 글이 재고에 남은 것으로 보인다.

## 3. 발행이 성공했는데 실패로 기록된다

인포노트는 오늘 13:04 에 발행에 **성공**했다.

```
09-01 13:04  인포노트  publish  success
```

같은 시각 실행 상태는 이렇다.

```
인포노트_워프  publish  성공 0  총실행 2  연속실패 2  마지막 13:04:09
```

**성공 로그가 남았는데 `successful_executions` 는 0이고 `consecutive_failures`
가 2다.** 즉 실제 발행 결과와 실행 상태 기록이 어긋나 있다.

이것이 1번 고리를 더 단단하게 만든다 — 성공해도 카운터가 안 올라가니
「최초 실행」 상태를 벗어나지 못한다.

### 부수 위험 — 자동 정지

연속 실패가 쌓이고 있다.

| 플로우 | 연속 실패 |
|---|---|
| 굿팁꿀팁_워프 | 21 |
| 인생꿀팁_워프 | 10 |
| 꿀팁대백과사전_워프 | 6 |

오토런에는 연속 실패가 쌓이면 자동 일시정지하는 장치가 있다. 실제로는
발행이 되고 있는데 실패로 기록되면 **멀쩡한 블로그가 자동 정지될 수 있다.**
현재는 세 플로우 모두 `active` 지만 임계에 가까워지고 있다.

## 4. 사용자가 본 현상과의 대응

> "성장 프로파일에서 이미 발행 횟수가 충족됐는데 계속 발행을 시도합니다"

정확히는 이렇다.

- **인포노트** — 오늘 1편 발행(GP 목표 1일 1편 충족). 13:04 성공 이후에는
  재시도하지 않았다. 다만 그 전까지 8회 스킵했고, 성공했는데도 상태는
  실패로 남았다.
- **굿팁꿀팁** — 오늘 0편. 목표를 채워서가 아니라 **재고가 카테고리에
  걸려 발행 후보가 못 되어** 30회 스킵했다.

즉 "횟수 충족인데 시도" 라기보다 **"발행할 수 없는 상태인데 멈추지도 않는
것"** 이 실제 현상이다. 일일 한도 체크 자체는 동작한다(한도 도달 시 다음
날로 스케줄).

## 5. 손대야 할 곳 (수정은 미진행)

| 순위 | 대상 | 내용 |
|---|---|---|
| 1 | `flow_scheduler.py` skip_interval 경로 | 재시도 횟수 상한 또는 카운터 갱신. 지금은 탈출구가 없다 |
| 2 | 발행 성공 시 상태 기록 | 성공했는데 실패로 남는 원인 규명 |
| 3 | 스킵 사유 | `describe_publish_block()` 를 skip 경로에서도 남기기 |
| 4 | 남은 재고 정리 | 카테고리에서 뺀 주제의 재고 4건 처리 방침 |

**1번을 먼저 고쳐야 한다.** 2번을 고치면 성공한 블로그는 빠져나오지만,
재고가 영영 없는 블로그(취업인포마스터 등)는 여전히 10분마다 돈다.

## 6. 정직하게 덧붙임

- 3번(성공인데 실패 기록)의 **정확한 원인은 아직 못 짚었다.**
  `_execute_publish_action` 은 `success: fail_count == 0` 을 돌려주므로
  성공 시 True 여야 한다. 다른 경로에서 상태가 덮이는지 더 봐야 한다.
- 10분마다 도는 것 자체가 큰 부하는 아니다. 다만 동작 로그가 스킵으로
  가득 차 **진짜 문제를 가린다** — 오늘 굿팁꿀팁 로그 30건이 전부 같은
  문구다.
- 카테고리 불일치 재고 4건은 지우거나 카테고리를 되살리면 해소된다.
  어느 쪽이 맞는지는 니치 정책에 달렸으므로 여기서 정하지 않았다.

# 추가 조사 — 생성 건너뜀 (2026-09-01)

> 지적: "굿팁꿀팁 GP 는 하루 2회인데, 09-01 로그 한 줄뿐인데도
> '오늘 2개 생성' 이라며 건너뛴다. 하루 1개 제한도 문제다."
> **두 지적 모두 맞다. 원인이 다르다.**

## A. "오늘 N개 생성" — 오늘이 아니라 최근 24시간이다

`flow_generate_executor._today_generated_count()`:

```python
start = datetime.now(timezone.utc) - timedelta(hours=24)
... GenerationHistory.created_at >= start
```

**함수 이름과 로그 문구는 "오늘" 인데 실제로는 굴러가는 24시간 창이다.**
자정으로 끊지 않는다.

### 실측으로 확인

굿팁꿀팁(blog 7) 생성 이력 — KST:

| 날짜 | 시각 |
|---|---|
| 08-31 | 11:06 |
| 08-31 | 22:04 |
| **09-01** | **없음** |

09-01 오전에 판정하면 `now-24h` 가 08-31 오전부터를 덮어 **어제 2건이
그대로 잡힌다.** 그래서 "오늘 2개 생성" 이 된다. 09-01 실제 생성은 0건이다.

인포노트(blog 18) — 지적한 08-31 12:13 사례:

| 날짜 | 시각 |
|---|---|
| 08-30 | 15:24 |
| 09-01 | 12:59 |

08-31 12:13 에 판정하면 `now-24h` = 08-30 12:13 부터 → **08-30 15:24 건이
잡혀** "오늘 1개 생성" 이 된다. 08-31 실제 생성은 0건이다.

**두 사례 모두 정확히 설명된다.**

### 왜 하필 지금 드러났나

이 함수는 색인 되먹임의 상한 판정에만 쓰인다. 상한이 1개로 내려간
블로그에서만 "1건만 있어도 막힘" 이 되어 증상이 보인다. 상한이 없던
때에는 이 값이 쓰이지 않아 문제가 드러나지 않았다.

### 영향 범위 (최근 7일)

| 블로그 | 건너뜀 |
|---|---|
| 군타 · 굿팁꿀팁 · 취업인포마스터 | 각 1 (09-01) |
| 슈마즈 · 인생꿀팁 · 인포노트 · 잡학다식 | 각 1 (08-31) |

7개 블로그가 이 판정으로 생성을 걸렀다. 어제 만든 글 때문에 오늘 못
만드는 구조라 **상한이 1인 블로그는 사실상 이틀에 한 번**만 생성된다.

## B. "하루 1개로 제한" — GP 와 연동되지 않는 것이 맞다

이것은 결함이 아니라 **설계다.** 색인 되먹임(`index_feedback.py`)이
GP 설정을 덮어쓴다.

```
색인률 30% 이상        → 제한 없음
색인률 10~30%          → GP 일일량의 절반
색인률 10% 미만        → 하루 1개
색인 0건 + 30일 경과   → 생성 중단
```

굿팁꿀팁은 「색인 0건(6일차)」 → 하루 1개.

### 그런데 지적이 타당한 지점

| 문제 | 내용 |
|---|---|
| 보이지 않는다 | GP 화면은 2회로 표시되는데 실제로는 1회다. 어디에도 안 나온다 |
| 되돌릴 수 없다 | 사용자가 이 상한을 끄거나 조정할 방법이 화면에 없다 |
| 이름이 어긋난다 | 로그가 "제한" 이라고만 해 GP 설정이 무시된 것으로 읽힌다 |

**설계 의도는 맞지만 사용자에게 설명되지 않는다.** 색인이 죽은 상태에서
발행을 늘리면 신호가 더 나빠지므로 상한 자체는 필요하다고 본다. 다만
GP 화면에 "색인 되먹임으로 현재 1개" 처럼 드러나야 한다.

### 6일차라는 숫자도 봐야 한다

`STOP_AFTER_DAYS = 30` 이므로 30일까지는 하루 1개로 버틴다. 굿팁꿀팁은
6일차다. 즉 **앞으로 24일 더 하루 1개**로 묶인다. 이것이 의도한 속도인지
판단이 필요하다.

## C. 두 문제가 겹치면

```mermaid
flowchart TD
    A[색인 0건 → 상한 1개] --> B[24시간 창으로 어제 생성분이 잡힘]
    B --> C[상한 1개를 이미 채운 것으로 판정]
    C --> D[오늘 생성 0건]
    D --> E[내일도 어제분이 잡힘]
```

상한이 1인 블로그는 **어제 만든 1건 때문에 오늘 못 만들고**, 그 결과
생성 간격이 계속 벌어진다. 굿팁꿀팁이 09-01 하루 종일 로그 한 줄인
이유다.

## D. 손대야 할 곳 (수정 미진행)

| 순위 | 대상 | 내용 |
|---|---|---|
| 1 | `_today_generated_count` | 24시간 창 → **KST 자정 기준 당일**로 |
| 2 | 로그 문구 | 세는 기준을 문구와 일치시키기 |
| 3 | GP 화면 | 색인 되먹임 상한을 표시 |
| 4 | 상한 조정 수단 | 사용자가 끄거나 완화할 수 있게 |

1번만 고쳐도 굿팁꿀팁은 오늘 2건(GP 설정)이 아니라 **1건(색인 상한)**
생성된다. GP 대로 2건을 만들려면 3·4번까지 함께 봐야 한다.

## E. 정직하게 덧붙임

- 이 24시간 창은 **내가 색인 되먹임을 넣으면서 함께 만든 것**이다.
  "오늘" 이라고 이름 붙이고 24시간으로 구현한 것이 원인이다.
- 자정 기준으로 바꾸면 자정 직후에 몰려 생성될 수 있다. GP 의 활성 시간대
  설정이 이를 어느 정도 막지만, 바꾼 뒤 실제 분포를 봐야 한다.
- B 항목(상한이 GP 를 덮는 것)을 없애야 하는지는 **판단이 필요하다.**
  색인 0건인 사이트에 발행을 늘리는 것은 진단서에서 지적한 바로 그
  행동이다. 다만 지금처럼 조용히 덮는 것은 잘못이다.
