# AI 모델 목록 갱신 방안 (제안 v2)

> 2026-08-30 · 상태: **제안 — 구현 전 승인 대기**
> v2 반영: 5단계 상세, 동기화 주기 사용자 설정, 추천 2종(최고성능·가성비),
> 모델별 비용 표시

## 1. 지금 상태

모델 목록이 **11개 파일에 따로따로 하드코딩**되어 있고, 목록을 내려주는 API가
없다. 화면마다 자기 목록을 갖고 있어 한 곳을 고쳐도 나머지는 그대로다.

| 파일 | 성격 |
|---|---|
| `templates/blogs/settings/_tab_ai.html` | 블로그 글쓰기/제목/참고자료 AI 선택 |
| `templates/modules/_prompt_form.html` | 프롬프트 모듈 (10건) |
| `static/js/settings.js` | 유사도 판정 모델 |
| `static/js/blog_image_settings.js`, `modules/list.js` | 이미지 |
| `services/reference_summary_service.py` | 요약 허용 모델·기본값 |
| `services/generation/reference_collector.py` | 참고자료 수집 |
| `services/generation/ai_image_service.py`, `image_param_converter.py` | 이미지 |
| `services/ai/ai_service.py` | 제공자별 기본 모델 |
| `services/ai/deepseek_pricing.py` | 딥시크 모델·요금 정의 |

## 2. 실제 피해 — 이미 발생 중

등록된 키로 각 제공자의 모델 목록 API를 직접 호출해 대조했다.
블로그가 쓰는 모델(36건)은 전부 유효하다. 문제는 **화면 선택지**다.

| 제공자 | 화면 선택지 | 이미 사라진 것 | 화면에 없는 신규 |
|---|---|---|---|
| OpenAI | 5개 | 0개 | 39개 (gpt-5 계열 등) |
| **Google** | 10개 | **5개** | 9개 (gemini-3.1/3.5 계열) |
| DeepSeek | 3개 | 0개 | 0개 |

사라진 구글 모델: `gemini-3-pro-preview`, `gemini-2.0-flash`,
`gemini-2.0-flash-lite`, `gemini-1.5-pro`, `gemini-1.5-flash`

**`gemini-3-pro-preview` 는 화면에서 "추천" 배지가 붙은 모델이다.**
추천대로 고르면 호출이 실패한다.

## 3. 각 API가 실제로 주는 것 (실측)

| 제공자 | 엔드포인트 | 개수 | 쓸 만한 메타데이터 |
|---|---|---|---|
| OpenAI | `GET /v1/models` | 126 | `id`, `created`, **`shutdown_date`** |
| Google | `GET /v1beta/models` | 50 | `displayName`, `description`, 토큰 한도, **`supportedGenerationMethods`**, `thinking` |
| DeepSeek | `GET /v1/models` | 3 | `id` 뿐 |
| Anthropic | `GET /v1/models` | – | 키 미등록으로 미확인 |

수확 두 가지:

- **OpenAI `shutdown_date`** — 126개 중 **52개에 종료일이 공지**돼 있다.
  사라지기 *전에* 경고할 수 있다.
- **Google `supportedGenerationMethods`** — 50개 중 `generateContent` 를
  지원하는 39개가 글 생성용이다. 용도 분류를 이름 규칙 없이 할 수 있다.

**요금 필드는 어느 API에도 없다.** 비용 표시는 우리가 따로 관리해야 한다(§6).

## 4. 구조

```
ai_models                          -- 목록(동기화로 갱신)
  provider, model_id, display_name
  capability        -- text | image | embedding …
  is_available      -- 마지막 동기화에서 목록에 있었는지
  shutdown_date     -- 제공자가 공지한 종료일(있으면)
  tier              -- flagship | value | (없음)   ← 추천 배지
  first_seen_at, last_seen_at, synced_at

ai_model_prices                    -- 요금(수동 관리)
  provider, model_id
  input_per_1m, output_per_1m, cached_input_per_1m
  currency, note, updated_at
```

- 화면은 `GET /api/v1/ai-models?provider=&capability=text` 로 받아 쓴다.
- **사라진 모델은 지우지 않고 `is_available=false` 로 남긴다.** 지우면 그
  설정이 무엇을 가리켰는지 알 수 없게 된다.

## 5. 5단계 — 무엇을 어떻게 나누는가

나누는 기준은 **"어디까지 하면 무엇이 되는가"** 다. 각 단계는 그 자체로
배포 가능하고, 앞 단계를 되돌리지 않아도 다음으로 넘어간다.

### 1단계 — 목록을 모은다 (화면 변화 없음)

| 만드는 것 | `ai_models` 테이블, 동기화 서비스, `GET /api/v1/ai-models` |
|---|---|
| **되는 것** | 서버가 "지금 어떤 모델이 살아 있는지" 안다 |
| **안 되는 것** | 화면은 여전히 하드코딩 목록을 쓴다 |
| 위험 | 없음 — 읽기만 추가, 기존 동작 무변경 |

이 단계만으로도 API를 호출해 현황을 확인할 수 있다. 화면을 건드리지 않아
회귀 위험이 없다.

### 2단계 — 사람이 갱신을 돌릴 수 있게 한다

| 만드는 것 | 설정 화면의 `지금 갱신` 버튼, 결과 요약 표시 |
|---|---|
| **되는 것** | 신규 모델 발표 직후 바로 반영. `신규 3 / 사라짐 1 / 유지 46` 확인 |
| **안 되는 것** | 아직 자동으로 돌지 않는다 |
| 위험 | 낮음 — 버튼을 누를 때만 동작 |

여기까지가 **"확인용"** 이다. 하드코딩은 그대로 두고, 무엇이 어긋나 있는지
눈으로 보는 단계.

### 3단계 — 블로그 AI 탭을 API 기반으로 바꾼다

| 만드는 것 | `_tab_ai.html` 의 `textProviders` 제거 → API 조회 |
|---|---|
| **되는 것** | 가장 자주 쓰는 화면에서 죽은 모델이 사라지고 신규가 나타난다 |
| 위험 | **중간** — 기존 설정이 목록에 없으면 선택이 비어 보일 수 있다 |

그래서 **저장된 값은 목록에 없어도 선택 상태를 유지**하고 `(지원 종료)` 를
붙인다. 이 규칙을 테스트로 고정한다. 구글 선택지 5개가 죽어 있으므로 이
단계에서 실제로 겪는다.

### 4단계 — 나머지 화면을 옮긴다

| 대상 | 프롬프트 모듈, 이미지 설정 2곳, 유사도 판정, 참고자료 요약 |
|---|---|
| **되는 것** | 하드코딩 제거 완료. 한 곳만 갱신하면 전 화면 반영 |
| 위험 | **중간** — 화면마다 목록 형식이 다르다 |

형식이 문자열 배열(`['gpt-4o-mini', …]`)과 객체(`{model_id, display_name}`)로
갈려 있어 **화면 단위로 나눠 배포**한다. 한 번에 바꾸면 어디서 깨졌는지
가려내기 어렵다.

### 5단계 — 자동화와 경고

| 만드는 것 | 주기 동기화 스케줄러, 사라짐/종료예정 경고 |
|---|---|
| **되는 것** | 손대지 않아도 목록이 최신. 쓰던 모델이 없어지면 알림 |
| 위험 | 낮음 — 실패해도 마지막 성공 목록을 쓴다 |

---

**요약하면**: 1\~2는 *알게 되는* 단계, 3\~4는 *하드코딩이 사라지는* 단계,
5는 *손을 떼는* 단계다. 3\~4가 가장 손이 많이 가고 위험도 여기 몰려 있다.

## 6. 비용 표시

### 왜 수동인가

모델 목록 API 어디에도 요금이 없다(실측 확인). OpenAI는 `id`/`created`/
`shutdown_date` 만, DeepSeek은 `id` 만 준다. 공식 요금 API도 없다.

### 방식

`ai_model_prices` 테이블에 **우리가 관리**한다. 딥시크에서 이미 쓰는 방식
(`deepseek_pricing.py`)을 전 제공자로 넓히는 것이다.

- **코드에 기본 요금표**를 두고 마이그레이션으로 시드한다.
- 요금이 바뀌면 **관리 화면에서 수정**한다(코드 배포 없이).
- 전체 126개가 아니라 **선택지에 올리는 10\~20개만** 관리한다. 나머지는
  비용 없이 표시하고 `요금 미등록` 으로 둔다.

### 화면 표시

```
글쓰기 AI
  ○ GPT-4.1 mini          입력 $0.40 / 출력 $1.60   [가성비]
  ○ GPT-5                 입력 $1.25 / 출력 $10.00  [최고 성능]
  ○ DeepSeek V4 Flash     입력 $0.22 / 출력 $0.66   [가성비]   ← 비피크 기준
  ○ Gemini 1.5 Pro        (지원 종료)
```

- 단위는 **100만 토큰당 USD**로 통일한다.
- 딥시크처럼 **시간대별 요금**이 있으면 비피크 기준으로 적고 주석을 단다.
- 글 한 편당 대략 비용도 함께 보여줄 수 있다(입력 3천 + 출력 4천 토큰 가정).
  다만 **어디까지나 추정치**이며 실제 청구액은 제공자 콘솔이 기준이다.

### 정직하게 말해 둘 것

요금은 **자동으로 최신이 되지 않는다.** 제공자가 가격을 바꾸면 우리가
고쳐야 하고, 그 전까지는 화면에 옛 가격이 뜬다. 그래서 `업데이트: 2026-08-30`
같은 갱신일을 함께 표시해 사용자가 오래된 값인지 판단할 수 있게 한다.

## 7. 추천 배지 — 최고 성능 / 가성비

API가 성능 정보를 주지 않으므로 **`tier` 를 사람이 지정**한다.
자동 추론(이름에 `pro` 가 있으면 플래그십 같은 규칙)은 오판이 잦아 쓰지 않는다.

| 배지 | 뜻 | 예 |
|---|---|---|
| **최고 성능** | 제공자의 플래그십. 품질 우선일 때 | GPT-5, Gemini 3.1 Pro, DeepSeek V4 Pro |
| **가성비** | 품질 대비 요금이 낮은 실무용 | GPT-4.1 mini, Gemini 3.5 Flash, DeepSeek V4 Flash |

- 제공자별로 각 배지 **1개씩만** 둔다. 여러 개면 배지 의미가 없어진다.
- 동기화로 **모델이 사라지면 배지도 함께 내려간다.** 지금 `gemini-3-pro-preview`
  에 추천 배지가 붙어 있는데 실제로는 없는 모델인 상황을 막는다.
- 기본 배지는 마이그레이션으로 넣고, 관리 화면에서 바꿀 수 있게 한다.

## 8. 동기화 주기 — 사용자 설정

기본 **1일**, 사용자가 바꿀 수 있다.

| 설정 | 값 |
|---|---|
| 주기 | 6시간 / 12시간 / **1일(기본)** / 3일 / 7일 / 사용하지 않음 |
| 실행 시각 | 기본 새벽 4시 (발행 시간대와 겹치지 않게) |
| 저장 위치 | `user_settings` (전역 설정 화면) |

- `사용하지 않음` 을 고르면 `지금 갱신` 버튼으로만 돌린다.
- 주기를 짧게 잡아도 **제공자 rate limit 에 부담이 없다** — 모델 목록 조회는
  글 생성과 별개의 가벼운 호출이고, 하루 몇 번 수준이다.
- 키가 없는 제공자는 건너뛴다(에러 아님). 한 제공자가 실패해도 나머지는 진행.
- 결과를 동작 로그에 남긴다.

## 9. 사라진 모델 경고

동기화에서 `is_available=false` 가 됐거나 `shutdown_date` 가 임박한 모델을
**현재 쓰고 있는 블로그**가 있으면 알린다.

- 블로그 설정 상단 배너: "이 블로그가 쓰는 `gemini-1.5-pro` 는 더 이상
  제공되지 않습니다. 다른 모델로 바꿔 주세요."
- 종료 예정은 미리: "`gpt-4o-mini` 는 2026-11-01 종료 예정입니다."
- 동작 로그에 WARNING.

**자동으로 바꾸지 않는다.** 모델이 바뀌면 글 품질과 요금이 달라진다.
gpt-4o-mini → gpt-4.1-mini 전환에서 분량이 1,618자 → 3,542자로 달라진 것처럼,
대체 선택은 사람이 해야 한다.

## 10. 주의할 점

- **기존 설정을 깨지 않는다.** 목록에 없는 모델이 저장돼 있어도 선택 상태는
  유지하고 `(지원 종료)` 표시만 붙인다.
- **동기화가 실패해도 화면은 열려야 한다.** 마지막으로 성공한 목록을 쓴다.
- **용도 분류**: Google은 `supportedGenerationMethods` 로 자동, OpenAI·DeepSeek은
  이름 규칙(`embed`/`tts`/`audio`/`image`/`realtime`/`whisper`/`moderation` 제외)
  + 관리 화면에서 수동 보정.

## 12. 확정된 사항 (2026-08-30 사용자 결정)

- 동기화 주기: **기본 1일 + 사용자 변경 가능**
- 추천 배지: **최고 성능 / 가성비 2종**
- 모델 옆 **비용 표시** (수동 관리 요금표 기반)

## 13. 남은 결정

**어디까지 진행할지** — 1\~2단계(확인용)만인지, 5단계까지 완주인지.
비용·배지 표시는 3단계(블로그 AI 탭)부터 화면에 나타난다.
