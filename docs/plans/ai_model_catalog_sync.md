# AI 모델 목록 갱신 방안 (제안)

> 2026-08-30 · 상태: **제안 — 구현 전 승인 대기**

## 1. 지금 상태

모델 목록이 **11개 파일에 따로따로 하드코딩**되어 있고, 목록을 내려주는 API가
없다. 화면마다 자기 목록을 갖고 있어 한 곳을 고쳐도 나머지는 그대로다.

| 파일 | 성격 |

| `templates/blogs/settings/_tab_ai.html` | 블로그 글쓰기/제목/참고자료 AI 선택 |
| `templates/modules/_prompt_form.html` | 프롬프트 모듈 (10건) |
| `static/js/settings.js` | 유사도 판정 모델 |
| `static/js/blog_image_settings.js`, `modules/list.js` | 이미지 |

| `services/generation/ai_image_service.py`, `image_param_converter.py` | 이미지 |

## 2. 실제 피해 — 이미 발생 중

등록된 키로 각 제공자의 모델 목록 API를 직접 호출해 대조했다.

**블로그가 쓰는 모델(36건)은 전부 유효하다.** 문제는 **화면 선택지**다.

| 제공자 | 화면 선택지 | 이미 사라진 것 | 화면에 없는 신규 |
|---|---|---|---|
| OpenAI | 5개 | 0개 | 39개 (gpt-5 계열 등) |
| **Google** | 10개 | **5개** | 9개 (gemini-3.1/3.5 계열) |
| DeepSeek | 3개 | 0개 | 0개 |

사라진 구글 모델 5개:
`gemini-3-pro-preview`, `gemini-2.0-flash`, `gemini-2.0-flash-lite`,
`gemini-1.5-pro`, `gemini-1.5-flash`

**그중 `gemini-3-pro-preview` 는 화면에서 "추천" 배지가 붙은 모델이다.**
사용자가 추천대로 고르면 호출이 실패한다. 지금 아무도 구글을 쓰지 않아
드러나지 않았을 뿐이다.

## 3. 전제 확인 — 네 제공자 모두 목록 API가 있다

문서만 보지 않고 실제로 호출해 확인했다.

| 제공자 | 엔드포인트 | 실측 |
|---|---|---|
| OpenAI | `GET /v1/models` | 126개 |
| Google | `GET /v1beta/models` | 50개 |
| DeepSeek | `GET /v1/models` (OpenAI 호환) | 3개 |
| Anthropic | `GET /v1/models` | 키 미등록으로 미확인(문서상 지원) |

자동 갱신은 기술적으로 가능하다.

## 4. 제안

### 4.1 구조 — 목록을 DB 한 곳으로

```
ai_models
  id, provider, model_id, display_name
  capability      -- text | image | embedding …  (용도 필터)
  is_available    -- 마지막 동기화에서 목록에 있었는지
  is_recommended  -- 화면 상단 노출(사람이 지정)
  first_seen_at, last_seen_at, synced_at
```

- 화면은 `GET /api/v1/ai-models?provider=&capability=text` 로 받아 쓴다.
  하드코딩을 지운다.
- **사라진 모델은 지우지 않고 `is_available=false` 로 남긴다.** 지워 버리면
  그 모델을 쓰던 블로그 설정이 무엇을 가리켰는지 알 수 없게 된다.

### 4.2 갱신 — 자동 + 수동 둘 다

| 방식 | 동작 |
|---|---|
| **자동** | 하루 1회(새벽) 등록된 키로 각 제공자 목록을 받아 반영 |
| **수동** | 설정 화면의 `지금 갱신` 버튼 — 신규 모델 발표 직후 바로 반영 |

- 키가 없는 제공자는 건너뛴다(에러 아님).
- 한 제공자가 실패해도 나머지는 진행한다.
- 결과를 동작 로그에 남긴다: `신규 3 / 사라짐 1 / 유지 46`.

### 4.3 사라진 모델 경고

동기화에서 `is_available=false` 가 된 모델을 **현재 쓰고 있는 블로그**가
있으면 알린다.

- 블로그 설정 화면 상단 배너: "이 블로그가 쓰는 `gemini-1.5-pro` 는 더 이상
  제공되지 않습니다. 다른 모델로 바꿔 주세요."
- 동작 로그에 WARNING.
- **자동으로 바꾸지 않는다.** 모델이 바뀌면 글 품질과 요금이 달라진다.
  앞서 gpt-4o-mini → gpt-4.1-mini 전환에서 분량이 1,618자 → 3,542자로
  달라진 것처럼, 대체 선택은 사람이 해야 한다.

### 4.4 용도 필터가 필요한 이유

OpenAI 126개 중 글쓰기에 쓸 수 있는 것은 일부다. 나머지는 임베딩·TTS·이미지·
실시간 음성이다. 그대로 내려주면 선택 목록이 쓸모없어진다.

1차는 **이름 규칙 + 수동 보정**으로 간다(`embed`/`tts`/`audio`/`image`/
`realtime`/`whisper`/`moderation` 제외). 규칙이 놓친 것은 관리 화면에서
`capability` 를 고칠 수 있게 한다. 제공자가 용도 메타데이터를 주지 않으므로
완전 자동 분류는 불가능하다.

## 5. 단계

| 단계 | 내용 | 비고 |
|---|---|---|
| **1** | `ai_models` 테이블 + 동기화 서비스 + 조회 API | 화면 변경 없음 |
| **2** | 수동 `지금 갱신` 버튼 + 결과 표시 | 여기서 실제 목록 확인 가능 |
| **3** | 블로그 AI 탭을 API 기반으로 교체 | 가장 자주 쓰는 화면부터 |
| **4** | 나머지 화면(프롬프트 모듈·이미지·유사도) 교체 | 하드코딩 제거 완료 |
| **5** | 일 1회 자동 동기화 + 사라진 모델 경고 | |

1~2단계만 해도 "지금 무엇이 살아 있는지" 확인할 수 있다. 3단계부터 실제
하드코딩이 사라진다.

## 6. 주의할 점

- **기존 설정을 깨지 않는다.** 목록에 없는 모델이 저장돼 있어도 선택 상태는
  유지하고 `(지원 종료)` 표시만 붙인다. 목록에서 사라졌다고 값을 지우면
  사용자가 모르는 사이 다른 모델로 글이 나간다.
- **동기화가 실패해도 화면은 열려야 한다.** 마지막으로 성공한 목록을 쓴다.
- **요금 정보는 목록 API에 없다.** 딥시크처럼 요금이 중요한 제공자는
  `deepseek_pricing` 방식으로 따로 관리한다.
- 모델 목록 조회는 키를 쓰므로, rate limit 을 피해 하루 1회로 제한한다.

## 7. 예상 작업량

| 단계 | 규모 |
|---|---|
| 1~2 | 테이블 1개, 서비스 1개, 라우터 2개, 화면 1곳 |
| 3~4 | 화면 6곳 교체(하드코딩 제거) |
| 5 | 스케줄러 1개 + 경고 표시 |

3~4단계가 가장 손이 많이 간다. 화면마다 목록 형식이 조금씩 달라
(문자열 배열 / `{model_id, display_name}` 객체) 한 번에 바꾸면 회귀
위험이 있으므로 화면 단위로 나눠 배포한다.

## 8. 결정이 필요한 것

1. **어디까지 진행할지** — 1~2단계(확인용)만인지, 5단계까지 완주인지
2. **자동 동기화 주기** — 하루 1회로 충분한지
3. **추천 모델 지정** — 사람이 고를지, 제공자 최신순으로 자동 표시할지
