# 자료 수집을 수작업 수준으로 — 검토

> 2026-09-15 · 검토 보고, 수정 없음

## 지금 무엇을 어떻게 찾고 있나

네이버 검색으로 **여섯 갈래**를 던집니다. 웹문서·뉴스·지식iN·카페·
백과·전문자료. 최대 30건을 찾아 10건을 읽고 **3건으로 요약**합니다.
요약 하나가 500자이니 글 한 편이 받는 자료는 **약 1,500자**입니다.

여섯 갈래로 나눈 것 자체는 옳습니다. 문제는 **찾는 곳이 네이버뿐**이라는
점입니다.

### 코드에 남은 잘못된 전제

지금 코드에는 이런 메모가 붙어 있습니다.

> 국가법령정보센터는 공개 검색 API 가 없어 (네이버 전문자료로) 대신한다

**사실이 아닙니다.** 법제처가 국가법령정보 공동활용 API 를 무료로
열어 두고 있고, 판례 목록·판례 본문·법령해석례까지 조회됩니다.
신청만 하면 됩니다.

퇴거 청소 글의 통상손모 법리, 파손 배상 글의 표준약관 30일 기한 —
제가 수작업으로 확인한 것들이 **바로 이 API 가 정확히 주는 것들**입니다.

---

## 세 가지 길

### 길 1 — 모델에게 직접 검색을 시킨다 (가장 빠름)

Gemini 에 구글 검색을 붙이는 기능이 있습니다. 켜면 모델이 **스스로
판단해 검색어를 만들고, 구글에서 찾고, 읽고, 그 근거로 글을 씁니다.**

**제가 수작업으로 하는 것과 구조가 같습니다.**

| | |
|---|---|
| 필요한 것 | **없음 — 구글 키가 이미 두 개 등록돼 있습니다** |
| 작업량 | 요청에 검색 도구를 켜는 설정 한 줄 |
| 요금 | 검색이 붙은 요청은 값이 조금 더 나갑니다 |
| 제약 | 검색을 켜면 다른 도구를 같이 못 씁니다 (지금 안 쓰므로 무관) |

**단, 글쓰기 모델을 Gemini 로 바꿔야 합니다.** 지금 이사노트는
deepseek 를 씁니다. 모델 선택(앞선 보고의 2번)과 맞물립니다.

또는 **자료 수집 단계만** Gemini 로 돌리고 글쓰기는 다른 모델로
둘 수도 있습니다. 자료 수집 모델은 이미 따로 정하게 되어 있습니다.

### 길 2 — 법령·판례를 정확히 가져온다

법제처 API 를 자료 수집의 한 갈래로 추가합니다.

| | |
|---|---|
| 필요한 것 | 법제처에 API 사용 신청 (무료) |
| 작업량 | 검색 갈래 하나 추가 — 지금 구조가 갈래를 여러 개 두게 돼 있어 |
| 요금 | 없음 |
| 효과 | **법 근거가 필요한 글에서 급이 달라집니다** |

이사·청소 니치는 법 근거를 묻는 질문이 많습니다. 원상복구 범위,
배상 기한, 표준약관 — 검색으로 요약된 2차 정보가 아니라 **원문**을
씁니다.

### 길 3 — 일반 웹 검색을 붙인다

구글 검색 API 를 자료 수집에 한 갈래로 추가합니다.

| | |
|---|---|
| 필요한 것 | 구글 검색 API 키 발급 |
| 작업량 | 검색 갈래 하나 추가 |
| 요금 | 하루 100건까지 무료, 넘으면 1,000건당 소액 |
| 효과 | 네이버 밖 자료가 들어옵니다 |

길 1과 겹칩니다. **길 1을 하면 길 3은 필요 없습니다.**

## 추천

| 순서 | 무엇 | 왜 |
|---|---|---|
| **1** | **법제처 API** (길 2) | 요금 없음 · 이 니치에 가장 잘 듣는다 |
| **2** | **자료 수집을 Gemini 검색으로** (길 1) | 키가 이미 있다 · 수작업과 구조가 같다 |
| — | 길 3 | 길 1을 하면 불필요 |

**둘을 함께 하면 제가 수작업으로 확인하는 자료의 대부분이 덮입니다.**

법제처 API 는 **신청이 필요합니다.** 신청 주체가 사용자여야 하므로
먼저 말씀해 주시면 발급받는 곳과 필요한 정보를 정리해 드리겠습니다.

Gemini 검색은 **지금 있는 키로 바로 됩니다.** 다만 자료 수집 모델을
Gemini 로 바꾸는 것이라, 글쓰기 모델 결정과 같이 보시는 편이 낫습니다.

## 남는 차이

셋 다 해도 하나는 남습니다. 제가 수작업으로 할 때는 **찾아보고 부족하면
다시 찾습니다.** 시스템은 한 번 찾고 끝냅니다.

지난주에 넣은 근거 체크리스트에 **한 번 더 찾는 장치**가 이미
들어 있습니다(모자란 항목을 넓혀 재검색). 지금은 한 바퀴만 돌게
막아 두었는데, 자료 출처가 좋아지면 이 제한을 푸는 것도 방법입니다.
