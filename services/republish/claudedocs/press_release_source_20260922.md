## 0. 결론

**보도자료는 "글 자체"가 아니라 "사실 소스(SourceFact)"로 쓴다.** 이 구조는 이미 `policy_briefing` 프리셋으로 구현돼 있고, 법적으로도 언론사 기사를 소스로 쓰는 것보다 깨끗하다. 진짜 리스크는 저작권이 아니라 **중복 콘텐츠**(같은 보도자료를 기반으로 한 글이 이미 수십 개)와 **이미지 별도 권리**다. 인터넷신문 등록은 필요 없다 — 보도자료는 공개 자료라 RSS·API로 동일하게 받는다.

## 2. 저작권 — 왜 기사보다 보도자료가 깨끗한가

정책브리핑 공식 해설(korea.kr, "보도자료로 작성한 기사, 저작권은 누구에게?"):
- 기관 보도자료를 **토씨만 바꿔 기사화하면 그 기사의 저작권은 보도자료를 낸 기관**에 있다.
- 기자가 주관적 사고·감정을 더한 기사는 언론사 저작물 → 재사용에 허락 필요.

→ 웹문서(언론사 기사) 요약은 저작권 경계가 애매하지만, **원본 보도자료는 공공저작물**이다.

| 소스 | 라이선스 | 조건 |
|---|---|---|
| 정부·지자체 보도자료 | 공공누리(대부분 **1유형**: 출처표시만 하면 상업·변경 가능) | 기관별 유형 확인. 출처 표시 형식: 기관명·연도·유형·저작물명 |
| 정책브리핑 "기사" 본문 | 공공누리 **4유형**(변경·상업 금지) | 기사가 아니라 **보도자료 원문**을 써야 함 |
| 보도자료 첨부 이미지·영상 | **별도 권리** | 기관 촬영이 아닐 수 있음. 텍스트와 분리 취급, 기본은 미사용 |

## 3. 무료 소스 목록 (2026-09-22 확인)

| 소스 | 접근 | 조건 | 상태 |
|---|---|---|---|
| **정책브리핑 API** | 공공데이터포털 | 인증키, 3일 범위 | **연결됨** |
| 부처별 RSS(행안부·재정경제부 등) | 각 누리집 RSS 메뉴 | 공공누리 | `korea.kr/etc/rss.do`는 메인으로 리다이렉트(302) — 부처별 URL을 개별 확인해야 함. 시도한 `mois.go.kr` RSS 경로는 404 |
| 지자체 보도자료 | 게시판 RSS / 일부 API(서울 열린데이터광장) | 공공누리, 지자체별 상이 | 미연결. 보도자료 전용 API는 드묾 |
| **뉴스와이어(기업 보도자료)** | `https://api.newswire.co.kr/rss/all` | 아래 §3.1 | **실작동 확인(200, 15건, lastBuildDate 2026-09-22)**. `www.newswire.co.kr/rss/all`은 404 — `api.` 서브도메인 사용 |
| 구글 뉴스 RSS | 이미 있음 | 제목만 | 본문 소스 부적합 |

### 3.1 뉴스와이어 조건(저작권 안내 `newswire.co.kr/?od=302`, FAQ `?ed=3&cat=18`)
- 언론사·블로거·웹사이트가 "대중에게 널리 알리기 위한 목적"으로 **무료** 사용 가능
- 전문 복제 시: **수정 없이 그대로 + 본문 앞 날짜·뉴스와이어 표시 유지 + 출처 기업 명시 + 원문 페이지 링크**
- **하루 5건 이상 복제 시 사전 허락** 필요
- 자기 사이트 외 제3 사이트 재배포·전송·판매 금지
- 내용 책임은 발표 기관·기업
- 요약·재작성 인용은 "보도 참고 목적" 범위로 해석되나, **5건/일 한도는 보수적으로 준수**

## 4. 리스크 — 저작권이 아니라 중복

1. **중복 콘텐츠**: 보도자료 1건 = 언론사 기사 수십 개 + 블로그 다수. 그대로 옮기면 수백 번째 사본. 색인 가치 없음 + 애드센스 "가치 없는 콘텐츠"(guntamoney 반려 사유와 동일 축) + 8/30 진단의 "검증 불가·형제 중복"을 다른 형태로 재생산.
2. **네이버 자체기사 기준** 참고: 문장 유사도 90% 이상 문장이 60% 이상이면 자체기사 제외. 같은 논리가 블로그에도 적용된다고 봐야 함.
3. **홍보문 오독**: 보도자료는 기관 홍보문. "검토 중"→"확정", "최대 48만원"→"48만원 지급" 같은 오류가 검증 없이 발생. **시행일·대상·조건·금액은 원문 수치 그대로, 해석은 분리.**
4. 이미지 무단 사용, 상표·인물 사진.

## 5. 적용안

**원칙**: 보도자료 = SourceFact. 글은 재작성. 원문 링크를 출처로 삽입. (현재 구조 유지)

| 순서 | 항목 | 코드 | 비고 |
|---|---|---|---|
| 1 | 정책브리핑 3일 제약 우회 | 소규모 | 키워드별 최근 N일을 3일 단위로 반복 호출, 또는 부처 RSS 보조. `_date_params`에 "최근 N일을 3일 창으로 순회" 옵션 |
| 2 | 뉴스와이어 RSS 소스 | 어댑터 또는 `data_go_kr` XML 경로 재사용 | `items_path: ["rss","channel","item"]` 로 `_from_xml` 이 받는지 실호출 확인. 필드 title/link/description/pubDate. **`daily_limit=5`** 로 약관 한도 강제. 기업·제품·IT 니치용 |
| 3 | 출처 자동 삽입 | 생성 후처리 | 본문 하단 "출처: OO부 보도자료(YYYY-MM-DD), 공공누리 제1유형" / "출처: 뉴스와이어(원문 링크)". 공공누리 출처표시 의무 이행 + 검증 가능 신호 |
| 4 | 형제 블로그 소스 중복 방지 | `exclude_sibling_titles`와 같은 축 | 같은 보도자료 ID(NewsItem id / newswire no)를 여러 블로그가 쓰지 않도록 소스 단위 잠금 |
| 5 | 부처 RSS 등록 | 등록만(확인 후) | 니치별 1~2개 부처(복지→보건복지부, 세금→국세청, 시니어→보건복지부·고용노동부) |
| 6 | 지자체 RSS | 등록만 | 거주 지역 1~2곳으로 지역 니치 실험 |

**하지 말 것**: 보도자료 전문 게재(뉴스와이어는 약관상 가능하나 중복 사본이라 SEO 무가치), 첨부 이미지 사용, 정책브리핑 "기사" 본문 재사용(4유형).

## 6. 인터넷신문 등록과의 관계

`project_internet_newspaper_startup`(메모리) 결론과 연결: 보도자료는 공개 자료라 **언론사 등록 없이 동일하게 접근** 가능. 등록의 이점은 기관 메일링 리스트 등재 정도인데 RSS·API가 그 역할을 대신한다. 보도자료 접근성은 인터넷신문 등록 이유가 되지 않는다.
