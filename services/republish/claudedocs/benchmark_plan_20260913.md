## 1. 먼저, 베끼지 말아야 할 것

대조해보니 **몇 가지는 우리가 이미 더 낫습니다.** 벤치마킹 목록에서 빼는 게 맞습니다.

### ① 어투 — 우리가 압도적으로 정교합니다

다마고치는 **3종**입니다. `~해요` / `~합니다` / `~한다`.

우리는 `prompt_builder/blocks_voice.py` (227줄)에 **페르소나 7종**이 있습니다.

| 코드 | 이름 |
|---|---|
| `P-Counselor` | 상담 창구 담당자 |
| `P-Reporter` | 제도 취재 기자 |
| `P-Clinician` | 임상 설명자 |
| `P-Cook` | 주방 실무자 |
| `P-Traveler` | 다녀온 사람 |
| `P-Fixer` | 문제 해결사 |
| `P-Curator` | 정보 정리자 |

어미가 아니라 **화자의 입장과 서술 원칙**을 정의합니다. 예를 들어 `P-Cook`은 *"계량·불세기·시간을 구체적으로 적고 '적당히' 같은 표현을 피한다"*까지 규정합니다. 차원이 다릅니다.

### ② 글자수 — 우리가 낫습니다

다마고치는 목표치를 입력받는 게 전부입니다(1300 설정 → 1500 산출, 오차 방치).

우리 `length_directive.py`는 임계값에서 **목표 분량·구획 수·구획당 분량**을 계산하고, **`continuation_prompt()`로 부족분을 이어 쓰게** 합니다.

### ③ 이미지 직접 업로드 — 이미 합니다

영상 1이 "외부 이미지 핫링크를 막으려고 직접 업로드를 강제한다"고 했는데, 우리는 `ImageUploader`로 imgbb에 올려 URL을 받아 씁니다.

### ④ 임시저장 후 검수 — 이미 있습니다

발행대기글 구조가 그대로 대응됩니다.

### 묶음 B — 판단을 넣는다 (핵심)

#### B-1. 자료 충분성 판정 + 재검색 루프 ★★품질 격차의 핵심

**현재**: `generator.py:333`의 `generate_content_with_meta()`는 **단발 호출**입니다. 참조 요약을 주입하고 한 번 부르면 끝이고, 재시도 루프는 **이미지에만** 있습니다.

즉 **자료가 부실해도 그대로 글 생성으로 넘어갑니다. 되돌아갈 경로가 코드에 없습니다.**

**수작업과의 대비**: 퇴거 청소 글은 `원상회복 법리` / `특약 유효성` / `보증금 분쟁 절차` 세 갈래를 따로 던졌고, 결과를 보고 무엇을 쓸지 골랐습니다.

**반영**

```
통합 요약 완료
    ↓
[신설] 충분성 판정 — "이 자료로 쟁점에 답할 수 있나"
    ↓ 부족
[신설] 질의 재설계 → 재검색 1회 (상한 고정)
    ↓
글 생성
```

**상한을 반드시 박습니다.** 재검색 1회, 총 추가 호출 2회 이내. 무한 루프는 비용이 통제되지 않습니다.

**난이도**: 중간. `reference_collector.py`(465줄)에 단계 추가 — 500줄 제한에 걸리므로 **판정 로직은 별도 모듈로 분리**해야 합니다.

#### B-2. 쟁점 설정 단계

**현재**: `reference_collector.py`의 ① 단계가 제목에서 **검색 질의**를 뽑습니다. 쟁점을 세우지 않습니다.

**수작업과의 대비**

| 주제 | 표면 질문 | 실제로 잡은 쟁점 |
|---|---|---|
| 퇴거 청소비 | 10만원 내야 하나 | **통상손모는 임차인 책임이 아니다** |
| 같은 건물 이사 | 일반이사 견적 | **분해·조립이 견적에서 빠진다** |
| 경유 이사 | 경유 가격 | **거리가 아니라 작업 횟수로 잡힌다** |
| 이사 종류 | 일반이냐 반포장이냐 | **"상하차만"은 용달 얘기다** |

쟁점이 없으면 글의 축도 없고, 검색 결과 나열이 됩니다.

**반영**: 질의 재작성 **앞에** "이 제목의 쟁점 2~3개" 추출 단계. 이후 질의·선별·구조가 모두 이 쟁점을 기준으로 움직입니다. **B-1의 판정 기준도 여기서 나옵니다** — 둘은 세트입니다.

**난이도**: 낮음(단계 자체) / 중간(후속 연결).

#### B-3. 주제 최신성 게이트

**현재**: `relevance.sort_by_freshness()`는 **정렬만** 합니다.

```python
dated   = [r for r in results if freshness_key(r)[0] == 1]
undated = [r for r in results if freshness_key(r)[0] == 0]
```

**문제 셋**
1. 배제가 아니라 정렬 — 3년 전 문서도 뒤에 남아 요약에 들어갑니다
2. 주제 자체의 시의성을 안 봅니다
3. 네이버 postdate는 재발행·수정일이 섞여 신뢰도가 낮습니다

**영상 근거**: 영상 1에서 처음 뽑은 주제 5개가 **이미 지난 자료 기반**이었고, 발표자가 이를 잡아낸 뒤 선별 기준까지 학습시켰습니다 — *최근 보도와 실제 변화가 있는가 / 국내 독자와 관련 있는가 / 궁금증을 만드는 각도인가*.

**반영**
- **제목 확정 전** 시의성 판정 (뉴스 소스 기반, A-1 의존)
- 참조 단계에서 **기준일 이전 문서 배제** 옵션. 니치별로 기준을 다르게 (제도·금융은 엄격, 생활 정보는 느슨)

**난이도**: 낮음.

#### B-4. AI 흔적 검사

**현재**: `quality_gate.py`(157줄)의 검사는 셋뿐입니다.

- `check_length()` · `check_risky_topic()` · `strip_duplicate_h1()`

**영상 근거**: 영상 1에서 *"점점점이 자동으로 나오는 건 AI 글 생성할 때 나오는 특수문자"* 라며 제거를 요청합니다.

**수작업 근거**: 이번 이사노트 글들은 매번 **상투어 13종 + 금지 태그 4종**을 스캔했고, 걸린 표현을 교체했습니다.

**반영**: `quality_gate`에 규칙 추가
- 특수문자 (`…`, `—` 남용 등)
- 상투어 사전 (`권합니다` · `이 부분` · `경우가 많습니다` · `가능성이 높` 등)
- 금지 태그 (`blockquote`, `<style`, `target=`, `rel=`)
- 1인칭 서술 빈도 하한 (경험담 프리셋에만)

**난이도**: 낮음. **보류해두신 항목이라 순서만 조정하면 됩니다.**

#### C-2. 구조 설계 단계

**수작업과의 대비**: 매번 구조가 달랐습니다. 퇴거 청소는 **법리 → 특약 → 금액 → 대응 절차**, 경유 이사는 **비교 → 요금 구조 → 동선 → 적재**. 쟁점이 다르니 구조도 달라진 겁니다.

**반영**: 본문 생성 전 **소제목 구성안**을 먼저 내고, 그걸 채우는 방식. B-2의 쟁점이 입력입니다.

**난이도**: 중간. 생성이 2단계가 되어 호출이 늘어납니다.

#### C-3. 노출 지면 역산 학습

**영상 근거**: 영상 1의 가장 특징적인 대목입니다. 추상 지시("기사체로 써줘") 대신 **홈피드에 실제 노출된 글들을 스크롤하며** 제목·본문 구조를 뽑았습니다.

**난이도**: 중간. 수집 경로는 있고 분석·반영 루프가 새로 필요합니다.

## 4. 실행 순서

효과가 앞의 것에 의존하는 관계를 반영했습니다.

```
1단계 ── A-1 검색 소스 확장 ★
         A-2 인기 검색어 소스
         A-3 태그 생성
         B-4 AI 흔적 검사
         ↓ (A-1이 아래를 받침)
2단계 ── B-2 쟁점 설정
         B-3 최신성 게이트
         ↓ (B-2가 판정 기준을 공급)
3단계 ── B-1 충분성 판정 + 재검색 루프 ★★
         ↓
4단계 ── C-1 지면별 프리셋
         C-2 구조 설계 단계
         C-3 노출 지면 역산 학습
         ↓
별도 ─── 네이버 자동화 (판단 대기)
```

**1단계는 서로 독립적이라 병렬 가능합니다.** 난이도가 모두 낮고, A-1만 끝나면 2·3단계가 열립니다.

**B-1이 최종 목표입니다.** 단발 파이프라인에 되돌아갈 경로 하나를 넣는 것이 에이전트 동작에 가장 크게 근접하는 변경입니다.

## 5. 비용에 대한 경고

**B-1·C-2를 넣으면 글 1편당 AI 호출이 늘어납니다.**

| 시점 | 호출 |
|---|---|
| 현재 | 질의 재작성 1 + 요약 1 + 생성 1 = **3회** |
| 반영 후 | 쟁점 1 + 질의 1 + 요약 1 + 판정 1 + (재검색 시 +2) + 구조 1 + 생성 1 = **6~8회** |

**두 배 이상입니다.** 그래서 두 가지를 미리 정해야 합니다.

1. **재검색 상한을 코드에 고정** — 1회, 추가 호출 2회 이내
2. **모델 배분 실측** — 가성비 모델로 루프를 도는 것과 상위 모델로 단발 하는 것 중 어느 쪽이 품질·비용에서 유리한지. 지금은 추정만 가능합니다

특히 2번은 **적용 전에 같은 제목으로 A/B를 돌려 확인하는 게 맞습니다.** 루프를 넣었는데 모델이 판정을 제대로 못 하면 호출만 늘고 품질은 그대로일 수 있습니다.
