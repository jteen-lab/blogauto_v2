# 손으로 쓸 때와 블로그 오토의 차이

> 2026-09-15 · 이사노트 26편을 쓴 과정을 되짚어 정리

## 1부 — 손으로 쓸 때의 순서

### ① 질문을 읽고 **진짜 쟁점**을 세운다

질문자가 묻는 것과 알아야 할 것이 다를 때가 많다.

> 퇴거 청소 질문: "청소비 15만원 달라는데 줘야 하나요"
> 실제 쟁점: 통상손모인가 과실인가 · 특약이 있었나 · 원상회복 범위는
> 어디까지인가 · 임의공제에 어떻게 대응하나

**질문에 없는 것을 넣는 판단이 여기서 일어난다.** 이사 종류 글에서
폐기물 처리를, 제주 이사 글에서 성수기 운임 구조를 넣은 것이 그렇다.

### ② 지금까지 쓴 글을 확인한다

이미 쓴 26편을 훑어 **겹치는 주제**와 **말투**를 맞춘다. 사다리차
비용을 앞에서 다뤘으면 이번엔 다르게 접근한다.

### ③ 쟁점마다 **따로** 검색한다

한 편에 보통 네댓 갈래를 던진다. 같은 글 안에서도 검색어가 다르다.

> 통상손모 판례 / 원상회복 특약 효력 / 퇴거 청소비 시세 /
> 보증금 공제 분쟁 사례

### ④ 결과를 읽고 **쓸 것을 고른다**

검색 결과를 그대로 쓰지 않는다. 광고성 글은 버리고, 오래된 제도는
빼고, 출처가 모호한 수치는 쓰지 않는다. **필요하면 원문 페이지를
열어 확인한다.**

### ⑤ 부족하면 **다시 찾는다**

여기가 가장 큰 차이다. ④에서 "이 쟁점은 근거가 약하다"고 판단하면
각도를 바꿔 다시 검색한다. **한 편에 이 되돌아감이 두세 번 일어난다.**

### ⑥ 구조를 짠다

```
도입(상황) → 먼저 결론 → 갈리는 지점 3~4개(표 포함)
→ 근거(법·기한) → 사례 → 정리 목록 → 개인 판단
```

### ⑦ 쓴다

1인칭 경험담. 금액·시기를 구체적으로. 인용문 없이.

### ⑧ 읽고 고친다

상투어가 섞였는지, 같은 말을 반복했는지, 분량이 맞는지 **직접 읽고**
고친다. 마음에 안 들면 문단째 다시 쓴다.

### ⑨ 형식을 갖춘다

HTML 변환 → 표지 이미지 생성 → 이미지 올리기 → 고지문·버튼 조립

## 2부 — 블로그 오토는 어떻게 하나

| 단계 | 손으로 | 블로그 오토 |
|---|---|---|
| 쟁점 세우기 | 사람 판단 | 근거 체크리스트(AI가 5항목) |
| 이전 글 확인 | 26편 훑음 | 유사도 검사(제목만) |
| 검색 | 쟁점마다 다른 말로 | 체크리스트가 만든 검색어 |
| 고르기 | 읽고 판단 | 관련도 관문(기계 판정) |
| **되돌아가기** | **두세 번** | **한 번(그것도 넓히기만)** |
| 구조 | 주제에 맞게 | 프롬프트에 박힌 틀 |
| 쓰기 | Claude | deepseek-v4-flash |
| 고치기 | 읽고 문단째 | 상투어 검사(있으면 경고) |
| 형식 | 손으로 | 자동 |

## 3부 — 차이가 나는 다섯 가지

### ① 되돌아감이 없다 ★ 가장 큰 차이

손으로 쓸 때는 **찾고 → 읽고 → 부족하면 다시 찾는다.** 이 고리가
한 편에 두세 번 돈다.

블로그 오토는 **한 번 찾고 끝낸다.** 체크리스트에 재검색이 한 번
있지만, 같은 항목을 **넓혀서** 다시 던질 뿐 "이 근거가 약하다"는
판단으로 각도를 바꾸지는 못한다.

### ② 판단하는 자리가 없다

손으로 쓸 때 판단은 **매 단계**에서 일어난다. 이 자료를 쓸까, 이
쟁점을 넣을까, 이 문단을 다시 쓸까.

블로그 오토의 판단은 **미리 정해진 규칙**이다. 관련도 점수가 몇 점
이상, 글자 수가 몇 자 이상. 규칙은 빠르지만 "이건 광고 글이다" 같은
판단은 못 한다.

### ③ 앞의 글을 모른다

손으로 쓸 때는 26편을 알고 쓴다. 겹치지 않게, 말투가 흔들리지 않게.

블로그 오토는 **글마다 새로 시작**한다. 제목 유사도만 본다. 같은
내용을 다른 제목으로 또 쓸 수 있다.

### ④ 글을 쓰는 모델이 다르다

| | 모델 |
|---|---|
| 손으로 | Claude |
| 블로그 오토 | deepseek-v4-flash |

프로젝트 안에 실측이 남아 있다 — 같은 프롬프트로 모델만 한 단계
올렸더니 **분량이 1,618자에서 3,542자**로 달라졌다.

### ⑤ 스스로 읽지 않는다

손으로 쓸 때는 다 쓰고 나서 **읽는다.** 어색하면 고친다.

블로그 오토의 검사는 **찾기**다. 상투어 목록에 있는 말이 있나,
글자 수가 되나. "이 문단은 앞과 같은 말이다" 같은 것은 못 본다.

## 4부 — 블로그 오토가 나은 것

공정하게 적는다. 아래는 손으로 하면 감당이 안 된다.

| | |
|---|---|
| **양** | 한 번에 여러 편, 여러 블로그 |
| **시각** | 표지 이미지 생성·업로드가 자동 |
| **발행** | 예약·재시도·실패 처리 |
| **중복 차단** | 제목 유사도 게이트 |
| **내부 링크** | 이전 글을 자동으로 엮음 |
| **되풀이** | 같은 품질로 계속 |

**손으로 쓰는 방식은 편당 비용이 크다.** 26편에 상당한 시간이 들었다.
블로그 오토는 그 비용을 낮추는 것이 목적이고, 낮춘 만큼 위의 다섯
가지를 잃었다.

## 5부 — 메우려면

이미 메운 것과 남은 것을 나눈다.

| 차이 | 상태 |
|---|---|
| 쟁점 세우기 | **메움** — 근거 체크리스트 |
| 검색처 | **메움** — Brave(같은 검색) + 법제처 원문 |
| 분량 | **메움** — 목표 4,200자 |
| 모델 | **남음** ← 가장 큼 |
| 되돌아감 | **남음** |
| 앞의 글 기억 | 남음 |
| 스스로 읽기 | 남음 |

### 남은 것을 메우는 방법

**모델** — 이사노트만 Claude 로 바꾸면 된다. 블로그마다 따로 정한다.
요금이 걸린 판단이라 사람이 정해야 한다.

**되돌아감** — 체크리스트가 "이 항목은 근거가 약하다"고 판정할 때
**검색어를 바꿔** 다시 던지게 한다. 지금은 넓히기만 한다. 다만 지금
채움 판정이 0% 로 나오고 있어, **그 판정부터 봐야 한다.**

**앞의 글 기억** — 글을 만들 때 그 블로그의 최근 글 제목과 소제목을
프롬프트에 함께 넣는다. 겹침이 줄어든다.

**스스로 읽기** — 다 쓴 글을 AI 에게 한 번 더 읽히고 고칠 곳을
받는다. AI 호출이 한 번 더 들어 **글당 요금이 오른다.**
