네이버 검색 API 는 **제목과 요약**만 줍니다. 요약은 실측 **127~135자**
입니다.

> 옷과 가방 등 포장 이사 하고 싶은데요. 포천에서 양주 아파트로 가야
> 하는데 옷만 포장 이사 가능할까요? 아직 날짜는... 안녕하세요~ 이사
> 전문업체 새집느낌입니다! 네, 옷과 가방 위주로도…

질문과 답변이 뒤섞여 잘린 형태입니다.

**그런데 이 요약은 이미 받아 오고 있었는데 화면에 그리지 않았습니다.**
제목만 보이던 이유가 그것이고, 방금 고쳐 배포했습니다.

질문 페이지를 실제로 열어 봤습니다.

질문과 답변이 **따로 뽑힙니다.** 섞이지 않습니다.

## 값어치

손으로 글을 쓸 때 질문에서 얻는 것은 **상황**입니다. 2층에서 3층으로,
엘리베이터 없음, 짐이 이 정도. 요약 130자로는 그게 잘려 나갑니다.

본문을 받으면 **질문자가 실제로 쓴 상황이 통째로** 들어옵니다. 답변까지
보면 그 바닥에서 통용되는 기준도 함께 옵니다.

## 대신 치러야 하는 것

| | |
|---|---|
| **속도** | 질문 하나에 한 번씩 페이지를 연다. 20건이면 20번 |
| **무게** | 한 페이지가 34만 자. 20건이면 7MB 를 받아 버린다 |
| **차단 위험** | 지금은 열리지만, 자주 긁으면 막힐 수 있다 |

**목록을 띄울 때 전부 긁으면 안 됩니다.** 검색 한 번에 20번 요청이
들어가고 화면이 한참 멈춥니다.

## 권하는 방식

**고른 질문만 본문을 가져옵니다.**

```
검색 → 제목·요약으로 훑기 (지금 그대로, 빠름)
     → 쓸 만한 것 몇 개 고르기
     → [내용 가져오기] 눌렀을 때만 그 몇 개만 본문 조회
     → 질문 본문 + 답변을 글 생성의 재료로 넘김
```

이러면 요청이 **고른 개수만큼**(보통 1~3건)입니다. 느려지지 않고
차단 위험도 낮습니다.

받은 본문은 글을 만들 때 **제목과 함께 넘겨** 쓰면 됩니다. 지금은
제목만 넘기고 있습니다.
