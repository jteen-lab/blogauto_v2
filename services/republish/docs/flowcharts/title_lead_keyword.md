# 검색어 중심 제목 재조합 N1~N4 (2026-10-23, 마케팅 지시·형 승인)

지시서: cheshirecat-app/data/프로젝트/마케팅/보고/2026-10-23_지시서_블로그오토_제목검색어_N1-N4.md

기존 재조합 스타일·프롬프트·trim_title·distinct_or_original·topic_gate·same_blog_dedupe 는
그대로 두고 **앞뒤에 붙인다**. 스위치는 모듈 settings 최상위 `title_lead_keyword` 하나 —
끄면 10/19 이전과 같다(N3·N4 는 스위치와 상관없이 모든 블로그).

코드: `lead_keyword_pick.py`(후보·고르기, 순수) · `lead_keyword.py`(조회·지시·맞춤·기록) ·
`volume_floor.py`(N2 건너뛰고 다음 제목) · `topic_gate.py`(N3 90일·N4 최종 제목)

## 1. 생성 회차 (flow_generate_executor)

```mermaid
flowchart TD
    A[제목 뽑기] --> G[제목 관문: 위험·지난연도·대출·제철·타블로그 중복·같은 블로그·거름망]
    G -- 걸림 --> S[이번만 건너뜀 / 영구면 보관]
    G -- 통과 --> F{title_lead_keyword 켜짐?<br/>CPA 오퍼 제목 아님?}
    F -- 아니오 --> W[글 생성]
    F -- 예 --> M{30일 안에 잰 검색량 있나}
    M -- 있음 --> C{검색량 ≥ 바닥선?<br/>기본 50 · 모듈 title_lead_floor}
    M -- 없음 --> Q[검색광고 1회 조회: 후보 최대 5개 + 연관어 전부]
    Q -- 실패 --> W
    Q -- 성공 --> R[가장 큰 검색량·잰 날을 main_titles 에 저장] --> C
    C -- 예 --> W
    C -- 아니오 --> N[검색량 낮음 — 보관 안 함, 같은 회차에서 다음 제목<br/>최대 3개, 30일 안에 잰 낮은 제목은 조회 없이 넘김]
    N --> A
```

## 2. 맨 앞 검색어 고르기 (lead_keyword_pick)

```mermaid
flowchart TD
    T[원래 제목] --> C1[title: 앞 낱말 2·3·1 묶음 + 핵심어]
    T --> C2[stripped: 앞 지역·연도 뺀 묶음 '고흥석류 효능'→'석류 효능']
    Q[조회 응답 전부] --> C3{related: 제목 낱말 앞·뒤 조각 + 일반어로만<br/>이뤄졌나? 제목 낱말 하나 이상?}
    C3 -- 아니오 --> X[버림 '비타민C효능'·'국민은행대출']
    C3 -- 예 --> P
    C1 --> P[바닥선↑ 후보: 두 낱말↑ 우선, 없으면 세 글자↑ 한 낱말]
    C2 --> P
    P --> L{제목이 지역 낱말로 시작하고<br/>그 지역 묶음이 바닥선↑?}
    L -- 예 --> K[지역 묶음]
    L -- 아니오 --> B[검색량 최대]
    B --> H{경쟁 높음·3만↑?}
    H -- 예 --> H2[그 말을 품은 더 긴 묶음 바닥선↑ 있으면 그쪽]
    H -- 아니오 --> E
    H2 --> E{고른 것이 related 이고<br/>title·stripped 후보가 1.5배 안?}
    E -- 예 --> O[원래 제목 쪽]
    E -- 아니오 --> K2[고른 검색어]
```

## 3. 재조합·맞춤·기록 (generator)

```mermaid
flowchart TD
    K[고른 검색어] --> I[재조합 지시에 덧붙임: 맨 앞 그대로·쉼표+알 수 있는 것 하나·고유명사 남김]
    I --> R1[재조합]
    R1 --> S1{맨 앞이 검색어?}
    S1 -- 예 --> Y
    S1 -- 아니오 --> R2[한 번만 다시 재조합] --> S2{맨 앞이 검색어?}
    S2 -- 예 --> Y
    S2 -- 아니오 --> FB[규칙: 「검색어」, + 재조합 결과에서 검색어 낱말 뺀 앞부분 30자]
    FB --> Y[trim_title → distinct_or_original]
    Y --> PY{N4 최종 제목에 지난 연도?}
    PY -- 예 --> ST[연도를 뺀 제목 + 본문 지시 '올해 기준 확인 안 된 숫자는 연도 밝혀 과거형']
    PY -- 아니오 --> BD
    ST --> BD[본문 지시: 검색어를 첫 문단 한 번 + 소제목 하나에]
    BD --> J[글 저장 뒤 logs/lead_keyword.jsonl 한 줄: 블로그·글·검색어·검색량·출처]
```

CPA 오퍼 제목(이사노트 등)은 지시를 붙이지 않고 검색어만 기록한다(N2 바닥선도 안 본다).

N2 '낮음'은 **모든 후보**(넓은 한 낱말 '삼겹살' 14만 포함)가 바닥선 아래일 때만이다.
검색량은 있는데 맨 앞에 쓸 말이 없으면(넓은 한 낱말뿐) 건너뛰지 않고 지시 없이 쓴다.
연관어는 제목에서 온 조각이 둘 이상이어야 한다('컴퓨터 가격'은 '그래픽카드 교체' 글 X).

검색광고가 검색량을 '< 10'으로 가려 보낼 때(2026-10-23부터 실측)는 클릭 ÷ 클릭률로
어림한다(naver_ads_service._count_or_estimate). 경쟁 정도도 '높음·중간·낮음' 한글로 온다.

## 4. N3 블로그끼리 같은 주제 (topic_gate)

- 7일 안: 지금 기준 그대로(바이그램 0.45 또는 낱말 2개↑·0.3)
- 8~90일: 의미 낱말 기준(same_blog_dedupe.is_same, 지역은 지우지 않음, 3개↑ 겹치면 같은 주제)
- 걸리면 이번만 건너뜀(보관 X)
- 같은 블로그: 모든 모듈 `dedupe_same_blog_days: 90`, doooit082.com 4곳은 `dedupe_sibling_sites` (인생꿀팁은 0=전체 기간 유지)
