# 참조자료 정확도 — 검색부터 주입까지

머니조아 실측(2026-09-06): 제목 "우리은행 우리아파트론 대출 금리와 방식" 으로
모은 자료 3건이 **신용대출 일반 · 주담대 일반 · 우리은행 대표전화 안내** 였다.
세 건 다 그 상품이 아니다. 관련성을 판단하는 지점이 한 곳도 없었다.

## 지금 (문제)

## 고친 뒤

```mermaid
flowchart TD
    T[제목] --> Q[① 질의 재작성<br/>개체 중심]

    Q --> R{③ 외부 소스<br/>레지스트리}
    R -->|니치·낱말 일치| API[공식 API<br/>금감원·공공데이터포털]
    R -->|없음| W

    API --> P[1차 출처<br/>맨 앞에 놓는다]
    API -->|부족| W[네이버 웹문서]

    W --> G1[② 관문 1<br/>제목·스니펫에 개체]
    G1 --> C[크롤링]
    C --> G2[② 관문 2<br/>본문에 개체]
    G2 --> S[⑤ 최신성 정렬<br/>오래된 것 뒤로]
    S --> PICK[상위에서 선택<br/>무작위 아님]
    PICK --> SUM[④ 통합 요약<br/>제목 + 전 문서 한 번에]
    SUM --> G3[② 관문 3<br/>'관련 없음' 제외]

    P --> INJ[프롬프트 주입]
    G3 --> INJ
```

## 왜 이 순서인가

**①②를 먼저** — 크기가 작고, 이번 실패(전화번호 페이지)는 관문 1에서 걸린다.
API 없이도 즉시 나아진다.

**③은 3a(틀)부터** — 3c(금감원)를 먼저 만들면 그게 곧 개별 연동이 되고,
나중에 레지스트리로 옮기는 일이 두 번 된다.

## 1차 출처를 못 찾으면

**억지로 비슷한 것을 붙이지 않는다.** 조용히 웹문서로 간다.
주담대 일반론이 "우리아파트론의 조건" 인 것처럼 들어간 것이 이번 사고다.

## 자동 선택 — 코드가 아니라 데이터로

```mermaid
flowchart LR
    A[제목 + 니치] --> B[(external_sources)]
    B --> C{match_topics ∩ 니치<br/>match_keywords ∩ 제목}
    C -->|일치| D[어댑터 호출]
    C -->|불일치| E[건너뜀]
```

새 API 는 화면에서 등록한다. 공공데이터포털은 인증·응답이 표준이라
**어댑터 하나로 여러 API** 를 받는다. 금감원처럼 자체 규격은 어댑터가 따로 필요하다.
