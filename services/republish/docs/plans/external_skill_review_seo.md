# 외부 스킬 검토 — fire-your-seo-agency (2026-08-28)

> 대상: https://github.com/leopard627/fire-your-seo-agency (MIT)
> 목적: A5 FAQPage 착수 전, 이 스킬을 도입할지 / 배제하고 자체 진행할지 판단

## 0. 결론

**도입도 배제도 아닌 '발췌'가 맞다.** 스킬 자체는 우리 구조에 맞지 않지만,
**NEO(네이버) 레인과 FAQPage 구현 디테일 2가지는 가져올 값이 있다.**
A5 는 원래 계획대로 자체 진행하되 아래 §4 의 조건을 추가한다.

## 1. 실체

- Claude Code **스킬(마크다운 지침)** 이다. 실행 코드가 아니다.
- 구성: `SKILL.md` + `references/{seo,aeo,geo,llmo,neo-naver,measure}.md`
- 동작: 에이전트가 한 사이트를 **감사 → 수정 → 재측정** 하는 컨설턴트형 절차.
- 라이선스 MIT — 발췌·재구현에 제약 없음.

## 2. 우리와 겹치는 부분 (도입 이득 없음)

| 레인 | 그쪽 | 우리 | 판정 |
|---|---|---|---|
| SEO | 사이트맵·robots·색인 요청 안내 | S1/S2/S6 **구현·배포 완료**, GSC API 실측 | 우리가 앞섬 |
| 측정 | **웹마스터도구 주간 수동 스냅샷** | URL Inspection API 자동 원장 | 우리가 앞섬 |
| AEO/FAQPage | "2023-08 이후 리치결과는 권위 도메인 한정" | **2026-05-07 FAQ 리치결과 폐지**까지 반영 | **우리가 더 최신** |

측정 규율("언제 뭘 다시 재는지까지가 완료 조건")은 옳은 원칙이나,
우리는 이미 스케줄러 + 원장으로 자동화했다.

## 3. 구조적 부적합 — 왜 통째로 쓰지 않는가

- 이 스킬은 **사이트 1개를 사람이 끼고 고치는** 절차다.
  blogauto 는 **11개 블로그에 수천 건을 자동 발행하는 생산 라인**이다.
- 그쪽의 조치는 **사이트 단위 1회성**(robots, 사이트맵, 페이지 스키마).
  우리에게 필요한 것은 **모든 글에 매번 적용되는 생성 시점 규칙**이다.
  스킬에는 생성 파이프라인·프롬프트라는 개념이 없다.
- 워드프레스/블로거 API 로 원격 수정하는 경로가 없다(파일시스템 접근 전제).
- "월 노출 164만" 류 수치는 검증 불가한 마케팅 문구다. **기법 자체는 표준 공개 문서**이며,
  README 도 그 점을 스스로 밝히고 있다.

## 4. 가져올 것 — 3가지

### (1) FAQPage 구현 조건 — A5 에 즉시 반영 ⭐
> "가시 텍스트와 JSON-LD 내용이 **정확히 일치**해야 한다. 불일치는 스팸 판정 유발."

우리 A5 는 "Q&A 블록과 1:1"까지만 적었다. **구현 시 본문 Q&A에서 문자열을 그대로
추출해 JSON-LD 를 만들도록 강제**한다(별도 생성 금지). 이 한 줄이 A5 설계를 바꾼다.

### (2) NEO(네이버) 점검 항목 — S2 확장, 소규모
우리에게 네이버 기술 점검이 **전무하다**. 가져올 항목:

| 항목 | 검증 방법 |
|---|---|
| robots.txt 가 **Yeti**(네이버 크롤러)를 막지 않는가 | 자동 점검 가능 |
| 네이버 서치어드바이저 **등록·사이트맵/RSS 제출** | 검증 메타 태그로 정황 확인 |
| AI 브리핑 인용 패턴: 산문보다 **키-값 표**, 1차 출처 명시, 기준일·산출근거 병기, 모바일 상단 배치 | 프롬프트 규칙 |

세 번째는 우리 A3(검증 가능한 사실)·A4(비교 표)와 **같은 축**이라 지시문 보강으로 끝난다.

### (3) 금지 사항 — 우리 판단과 일치(확증)
자동 맞팔·댓글 품앗이·반복 중복 텍스트·잦은 사후 수정은 저품질 유발.
`external_traffic_strategy.md` 의 C등급 배제와 동일 결론.

## 5. 실측 — 가져온 항목을 우리 사이트에 적용해봄

### 5.1 Yeti 차단 여부 (11개 전수) — **문제 없음**
전 블로그가 `User-agent: *` 에 `Disallow:`(빈 값) 또는 `Allow: /`.
**Yeti 를 막는 곳은 하나도 없다.** 이 항목은 점검 가치는 있으나 현재 결함 아님.

### 5.2 검증 메타 태그 (워드프레스 6개)

| 사이트 | 네이버 | 구글 |
|---|---|---|
| doooit082.com | ✅ | ✅ |
| blog01.doooit082.com | ✅ | ✅ |
| fund.doooit082.com | ✅ | ❌ |
| lifein4.com | ❌ | ✅ |
| **in4note.co.kr** | ❌ | ❌ |
| **info.doooit082.com** | ❌ | ❌ |

> ⚠️ 소유 확인은 HTML 파일·DNS 로도 가능하므로 **메타 태그 부재 = 미등록이 아니다.**
> 실제로 in4note.co.kr 은 메타가 없지만 GSC 속성으로는 잡혔다(§`search_visibility_plan` §10).
> 즉 이 신호는 **정황**이지 확증이 아니다.

그럼에도 GSC 실측과 교차하면 **info.doooit082.com·fund.doooit082.com 은 속성 미등록**이
이미 확인됐고, 네이버 쪽도 3곳이 의심된다 → 사용자 점검 대상.
