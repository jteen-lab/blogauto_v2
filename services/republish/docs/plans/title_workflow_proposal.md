## 2. 용어 정리 — 지금 "제목 생성" 이 두 개다

혼동의 원인이므로 먼저 나눈다. 둘은 경쟁 관계가 아니라 **직렬**이다.

```
[생산]  키워드 → 클러스터 → AI 제목 → 관문 → main_titles
        (title_gen 모듈 · 재고를 만든다)
                      ↓
[소비]  main_titles 에서 1건 꺼냄 → AI 재조합(스타일) → 발행
        (TitleRecombiner · generator.py 2단계 · 재고를 쓴다)
```

말씀하신 "정식제목을 AI 로 재조합" 은 **소비 쪽**이다. 재고를 만드는
단계가 아니라, 재고에서 꺼낸 제목을 발행 직전에 다듬는 단계다.

→ **둘 중 하나를 고르는 문제가 아니다.** 생산을 바꾸는 것과 재조합을
   유지·보완하는 것은 별개로 결정할 수 있다.

## 3. 제목 수집·생성 — 3층 구조 제안

한 가지 방식으로 전부 덮으려 하면 각각의 약점이 그대로 남는다.
소재의 성격이 다르므로 층을 나눈다.

### L1. 생성 (주력) — 이미 구현됨, 미가동

```
채택 키워드 → 질문 팬아웃 → 클러스터 → 각도 조회 → AI → 관문
```

- 니치가 보장된다(키워드가 이미 분류·판정을 통과했다)
- 대표 글 1편 + 곁가지 N편으로 **양이 나온다**
- 검색량·포화도를 알고 만든다

**약점**: 시의성 소재를 못 만든다. AI 는 이번 주에 무슨 일이 있었는지
모른다.

### L2. 수집 (보조) — 각도 신호로만, 이미 구현됨

경쟁 제목은 재고로 쓰지 않고 "이미 포화된 각도" 신호로만 쓴다.
원문을 저장하지 않으므로 저작권·최신성 문제가 없다.

**이 층을 재고화로 되돌리면 안 된다.** 통과율 2% 의 원인이 그것이었다.

### L3. 시의성 (신설 제안) — 뉴스 소재

`news_collect` 로 이미 18,315건이 들어와 있다. L1 이 못 하는 자리를
정확히 메운다.

단, **원문 제목을 재고에 넣지 않는다.** L2 와 같은 원칙이다.

```
[옛] 뉴스 제목 → 임시제목(재고)         ← 남의 제목, 최신성 만료
[새] 뉴스 → "무슨 일이 있었나" 요지 추출 → 우리 니치 키워드와 결합 → AI 제목
```

예: "전기요금 개편안 발표" (뉴스) + "전기기사" (우리 니치)
→ "전기요금 개편이 전기기사 수요에 미치는 영향"

**결정 필요**: L3 를 살릴지. 지금 18,315건은 원문이라 그대로는 쓸 수 없다.

## 4. 정식제목 AI 재조합 — **유지하되 보완**

### 유지해야 하는 이유

재고 하나를 여러 블로그가 나눠 쓴다. 재조합이 없으면 같은 제목이 여러
블로그에 그대로 나간다. **발행 시점 변형은 필요하다.**

### 확인된 문제 3가지 (코드 근거)

**① 스타일이 랜덤인데 성과를 추적하지 않는다**

```python
# generator.py:165
selected_style = random.choice(tr_styles) if tr_styles else None
```

5개 스타일(감성·실용·질문·바이럴·심플) 중 하나를 무작위로 고른다.
그런데 `generation_history` 에 **어떤 스타일을 썼는지 컬럼이 없다.**

→ 무엇이 먹히는지 영원히 알 수 없다. 1년을 돌려도 학습이 0이다.

**② 재조합이 원본 제목 문자열만 본다**

```python
# title_recombiner.py 기본 프롬프트
"원본 제목: {title}"
```

키워드의 검색량도, 포화도도, 경쟁 각도도 넣지 않는다. 생성 단계에서
각도를 피해 만든 제목을, 재조합이 그 각도로 되돌려 놓을 수 있다.

**③ 재조합 결과에 중복·유사도 검사가 없다**

생산 단계는 관문(금지어 → 분류 → 유사도)을 통과한다. 그런데 재조합은
그 뒤에 일어나므로 **관문 밖**이다. 재조합 결과가 이미 발행한 제목과
겹쳐도 걸러지지 않는다.

### 보완 제안 (우선순위 순)

| 안 | 내용 | 비용 |
|---|---|---|
| **A** | `generation_history` 에 `title_style` 기록 → GSC 성과와 대조 → 성과 좋은 스타일에 **가중치**를 준 무작위 선택 | 컬럼 1개 + 집계 |
| **B** | 재조합 프롬프트에 **핵심 키워드**를 함께 넣어 유실 방지 (`main_titles.matched_keyword`) | 프롬프트 수정 |
| **C** | 재조합 결과를 **유사도 검사**에 태워, 기존 발행 제목과 겹치면 1회 재시도 | 기존 matcher 재사용 |

A 가 가장 값싸고 효과가 크다. 지금은 5개 스타일을 굴리면서 아무것도
배우지 않는 상태다.

## 5. 임시제목 탭에 어떻게 녹일 것인가

### 성격 재정의

| | 지금 | 제안 |
|---|---|---|
| 역할 | 크롤링 원문 대기실 | **관문 대기실 + 회수 큐** |
| 들어오는 것 | 크롤링 제목 | 생성 제목 중 **분류 실패분** |
| 나가는 것 | 재분류 후 정식제목 | 같음 |
| 볼 이유 | 목록 훑기 | **분류표에 무엇이 빠졌는지 진단** |

미분류 제목은 버릴 쓰레기가 아니라 **"분류표에 이 주제가 없다"는 신호**다.
그 관점으로 화면을 바꾼다.

### 화면 제안 3가지

**① 출처 배지 + 필터** — 지금은 세 출처가 구분 없이 섞여 있다

```
[전체] [생성 0] [수집 86,311] [뉴스 18,315]
```

출처마다 취해야 할 행동이 다르다. 생성분 미분류는 분류표를 손봐야 하고,
수집분은 정리 대상이다.

**② 제목 생성 실행 패널** — 키워드 탭의 수동 수집과 같은 패턴

키워드 탭에 이미 "🔎 키워드 수집" 패널이 있고, 자동 모듈과 **같은
실행기**를 사람이 손으로 돌린다. 제목도 같은 구조로:

```
✍️ 제목 생성 — 채택 키워드로 제목 만들기
  대상 블로그 [        ]   검증 모드 ☑ (저장 안 하고 결과만)
  [실행]  → 결과: 클러스터 3개 · 제목 12편 · 관문 통과 9 · 회수 3
```

지금은 모듈을 만들고 플로우에 넣어야만 돌릴 수 있다. 그래서 **한 번도
안 돌아간 채로 남아 있다.** 화면에서 바로 돌려 볼 수 있어야 한다.

**③ 미분류 사유 요약** — 회수 큐를 진단 도구로

```
미분류 64,575건 중 상위 주제어
  "재테크" 관련 1,204건 → 분류표에 없음
  "여행"   관련   892건 → 분류표에 없음
```

무엇을 분류표에 추가하면 몇 건이 살아나는지 보여 준다. 지금은 재분류를
돌려 봐야만 알 수 있다.
