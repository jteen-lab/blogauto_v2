# 애드센스 승인 자동화 + 검색 노출 개선 통합 작업계획서

> 작성 2026-08-21 | 검색 노출 파트 통합 2026-08-23 | 상태: 검토 완료 · 착수 대기 | 수정 미진행
> 관련 [[adsense_module_ui_migration]] [[flow_module_blog_scope_plan]]
> [[adsense_required_pages_module_plan]] [[search_visibility_plan]] [[niche_title_aeo_plan]]

**이 문서가 실행 기준이다.** 검색 노출 조사의 상세 근거(실측 로그·정책 원문 링크)는
[[search_visibility_plan]] 에 남기고, 여기서는 실행 항목과 순서만 통합해 관리한다.

## 0. 두 과제의 관계

애드센스 승인과 검색 노출은 별개 과제로 보이지만 **원인이 상당 부분 겹친다.**

| 겹치는 원인 | 애드센스 영향 | 검색 노출 영향 |
|---|---|---|
| 같은 제목 글 639건 중복 | 가치 없는 콘텐츠 판정 | 중복 콘텐츠 |
| 편집 감독 없는 대량 발행 | scaled content abuse 반려 | 2026-03 코어 업데이트 타깃 |
| 서브도메인 구조 | 승인 상태가 부모 도메인에 종속 | 신뢰도를 각자 축적, 색인 지연 |

→ 승인을 위해 하는 일(니치 집중·1일1포·정보이득)이 **검색 노출에도 그대로 이득**이다.
따라서 애드센스 파트를 먼저 하고 검색 파트를 잇는 순서가 낭비가 적다.

## 1. 배경

애드센스 승인용 기능(F4 니치 강제 · F7 정보이득 · 필수페이지 · 성장 프로파일
애드센스 프리셋)이 블로그 설정 / 프롬프트·생성 모듈 / 성장 프로파일 모듈 **세 곳에
흩어져** 있고, 서로를 참조하지 않는다. 블로그가 수십 개면 승인 전후로 설정을 일일이
바꿔야 해 누락이 불가피하다.

블로그 설정의 `adsense_status`(none/preparing/applied/approved)는 **저장·표시만 되고
동작에 아무 영향을 주지 않는다**(코드 전수 확인). 이 값을 축으로 삼아 승인 전후 동작을
자동 전환하는 것이 이 계획의 목표다.

## 2. 검토 결과 (2026-08-21)

### 2.1 애드센스 API로 승인 상태 자동 감지 — 가능
- `accounts.sites.list/get` → `state`: REQUIRES_REVIEW / GETTING_READY / READY /
  NEEDS_ATTENTION. `accounts.get` → `pendingTasks`(결제·전화인증 등 미완료 작업).
- OAuth 범위 `adsense.readonly` 필요 → **기존 Blogger refresh_token 재발급 필요**.
- 애드센스 계정 자체는 승인과 무관하게 생성 가능(사용자 보유). 따라서 API 접근은 가능.

### 2.2 ⚠️ 서브도메인 — 사이트 목록에 나타나지 않는다 (핵심 함정)
AdSense는 2023-03-20부터 **도메인 단위**로 사이트를 관리하며, 서브도메인은 목록에서
제거되고 **부모 도메인의 상태를 따른다**.

현재 등록 블로그 실측:

| 블로그 | 주소 | 사이트 목록 노출 |
|---|---|---|
| 인생꿀팁 | doooit082.com | ✅ 노출 |
| 굿팁꿀팁 | info.doooit082.com | ❌ 미노출(부모 상태 상속) |
| 꿀팁대백과사전 | fund.doooit082.com | ❌ 미노출 |
| 잡학다식 | blog01.doooit082.com | ❌ 미노출 |
| 블로그스팟 5개 | *.blogspot.com | ✅ 파트너 사이트로 개별 노출·개별 심사 |

→ "목록에 없으면 미신청"이라는 단순 규칙을 그대로 쓰면 **워드프레스 서브도메인 3개가
영구 미신청으로 오판**되어, 승인 후에도 애드센스 모드가 해제되지 않는다.

**매칭 규칙(필수)**
1. 블로그 URL → 호스트 정규화(스킴·끝 슬래시·대소문자·www 제거)
2. 사이트 목록에 정확히 있으면 그 상태 사용
3. 없으면 **상위 도메인으로 거슬러 올라가며** 탐색(`info.doooit082.com` → `doooit082.com`)
4. 끝까지 없으면 **그때가 진짜 미신청**
5. 상속으로 판정된 블로그는 상태 표시에 "상위 도메인 기준"임을 노출

부작용(수용): `doooit082.com` 계열 4개 블로그는 **항상 같은 상태를 공유**한다.
애드센스가 도메인 단위로 판정하므로 이것이 정확한 동작이다.

### 2.3 니치 주제는 모듈에 유지 (앞선 권고 정정)
초기 검토에서 "니치 주제를 블로그 설정으로 이전" 을 권고했으나 **철회한다.**
- 이전 시: 블로그 100개면 설정 지점 100곳, 확인도 블로그별로 해야 함.
- 유지 시: 니치별 공용 모듈 3~4개만 관리하면 되고 니치 구성이 한눈에 보인다.
- 니치 강제가 카테고리 설정을 전부 덮으므로 **한 모듈을 여러 블로그에 붙여도 주제가
  섞이지 않는다** — 이미 현재 구조가 이 사용법을 지원한다.

목표 구성:
```
[일반 플로우]                        [애드센스 플로우]
플로우A: 일반모듈A + 블로그A     플로우N1: 공용니치모듈1 + 블로그 A,B,C
플로우B: 일반모듈B + 블로그B     플로우N2: 공용니치모듈2 + 블로그 D,E
플로우C: 일반모듈C + 블로그C     플로우N3: 공용니치모듈3 + 블로그 F,G
```
2026-08-21 배포한 규칙과 충돌 없음:
- "모듈은 플로우 한 곳만" — 공용 모듈은 각자 애드센스 플로우에만 존재 ✅
- "모듈 연동 블로그로 범위 고정" — 애드센스 플로우 블로그가 자동 고정 ✅
- 블로그가 두 플로우에 속하는 것은 현재도 허용 ✅

## 3. 설계

### 3.1 모듈 역할(role) + 블로그별 활성 판정
모듈에 켜고 끄는 플래그가 **현재 존재하지 않는다**(Module·FlowModule 모두 없음).
모듈을 통째로 끄는 방식은 **금지** — 공용 모듈에 붙은 블로그 중 일부만 승인되면
아직 심사 중인 블로그까지 멈춘다.

`Module.settings.adsense_role` (기본 `always`, 스키마 변경 불필요):

| 값 | 실행 조건 |
|---|---|
| `adsense_only` | 그 블로그가 승인 전(none/preparing/applied)일 때만 |
| `post_approval` | 그 블로그가 승인(approved) 이후에만 |
| `always` | 상태 무관 (기존 모듈 전부 이 값 = 하위호환) |

판정 위치: `app/services/flow/module_blog_scope.py::blogs_for_module()` 에 상태 조건
추가(2026-08-21 신설). 오토런·1회 실행·백그라운드 세 경로가 이미 이 함수를 통과한다.

동작 예:
```
블로그 A(승인) → 공용니치모듈1 건너뜀 / 일반모듈A 실행
블로그 B(심사중) → 공용니치모듈1 실행 / 일반모듈B 건너뜀
```

### 3.2 동일 모듈 내 전환(모듈 통합형)도 병행 지원
별도 모듈을 쓰지 않고 한 모듈에 애드센스 옵션을 담는 기존 방식도 유지한다.
`niche_enabled` / `info_gain_enabled` 를 **고정값이 아니라 조건부**로:
- `adsense_auto: true` 이면 실행 시 블로그 상태를 읽어
  승인 전 → 니치·정보이득 ON, 승인 후 → OFF(원래 카테고리 기준)
- `adsense_auto: false`(기본) 이면 지금처럼 사용자가 켠 값 그대로

### 3.3 성장 프로파일 프리셋 전환
> **정정(2026-08-23)**: 프리셋 식별자는 이미 저장되고 있다. 키 이름이 `profile_key`가
> 아니라 **`selectedPreset`** 이라 앞선 조회에서 빈 값으로 보였을 뿐이다.
> 실측: aggressive(군타) · adsense(수작남) · conservative(머니조아 외 3) · custom_1(5개).
- 따라서 남은 작업은 **원본 스냅샷 보관·복원**뿐이다.
- 구현: `app/services/generation/growth_profile_adsense.py`
  - `apply_adsense_preset()` — 원본을 `settings.adsense_base_profile` 로 보관 후 adsense 적용.
    **이미 애드센스면 스냅샷을 덮어쓰지 않는다**(두 번 호출해도 원본 보존)
  - `restore_base_profile()` — 스냅샷으로 복원. **스냅샷이 없으면 아무것도 하지 않는다**
    (임의 기본값으로 덮으면 사용자가 손으로 맞춘 설정이 사라진다)
  - 보관 대상: selectedPreset · schedule_matrix · jitter · stages · warmup · custom_profiles
- 자동 호출은 상태 동기화(9단계)·모듈 통합형 전환(10단계)에서 연결하며,
  `settings.adsense_auto` 로 **옵트인**한 프로파일에만 적용한다.

### 3.4 상태 전환 자동화

| 전환 | 계기 | 방식 |
|---|---|---|
| none → preparing | 필수페이지 4종 생성 완료 | 내부 이벤트(즉시 적용 가능) |
| preparing → applied | 사이트 목록에 REQUIRES_REVIEW 등장 | API 동기화 |
| applied → approved | 사이트 상태 READY | API 동기화 |
| approved → 기능 해제 | 위와 동시 | 3.1~3.3이 자동 반영 |
| * → NEEDS_ATTENTION | 사이트 문제 발생 | 경고 표시(자동 해제 금지) |

동기화 주기: 스케줄러 잡 하루 1~2회. 수동 "지금 확인" 버튼 병행.

### 3.5 ⚠️ 형제 블로그 간 제목 중복 방지 (신규 발견 · 우선순위 높음)
운영 데이터 실측: **639개 제목이 2개 이상 블로그에서 사용**됨(최대 10개 블로그).
현재 설계상 다른 블로그가 쓴 제목은 후보에서 배제하지 않는다(같은 블로그 재사용만 차단).

- 니치 강제를 켜면 제목 풀이 좁아져 **중복 확률이 크게 상승**한다.
- `doooit082.com` 계열 4개는 **같은 도메인** — 같은 제목 반복이 특히 불리하다.
- 애드센스 반려 사유(가치 없는 콘텐츠 / scaled content abuse)에 정면으로 걸린다.

대책: 공용 니치 모듈에 연결된 블로그끼리는 **이미 형제 블로그가 사용한 제목을 후보에서
제외**하는 옵션(`exclude_sibling_titles`). 재고 부족 시 생성이 스킵되므로 니치별 제목
재고 확보가 선행돼야 한다.

## 4. 블로그 카드 애드센스 상태 표시 (2026-08-21 사용자 요청)

### 4.1 현황
- `blogs/_card.html` 에 **상태 뱃지 영역이 이미 존재**(자동 발행 / 크롤링·매칭 상태)
  → 같은 줄에 추가하는 것이 자연스럽다.
- 단, **`BlogResponse` 스키마에 `adsense_status`가 없다** → 필드 추가 필요.
  `required_pages_status` 도 함께 내려주면 준비도 표시에 쓸 수 있다.

### 4.2 뱃지 설계 (채택안)
| 상태 | 표시 | 색 |
|---|---|---|
| none | `애드센스 미신청` | 회색 |
| preparing | `애드센스 준비중` | 노랑 |
| applied | `애드센스 심사중` (점 깜빡임) | 파랑 |
| approved | `애드센스 승인` | 초록 |
| NEEDS_ATTENTION 감지 시 | `애드센스 확인 필요` | 빨강 |

- 상위 도메인에서 상속받은 상태는 뱃지에 `(도메인 기준)` 병기 — 서브도메인 3개가
  왜 부모와 같은 상태인지 사용자가 납득할 수 있어야 한다.
- 뱃지에 마지막 동기화 시각을 tooltip 으로 노출.

### 4.3 함께 제안하는 보조 수단
블로그가 수십 개가 되면 카드 뱃지만으로는 한눈에 안 들어온다. 다음을 병행 권장.

1. **목록 상단 요약 칩** — `승인 3 · 심사중 2 · 준비중 4 · 미신청 2`,
   클릭 시 해당 상태만 필터. 블로그가 많아질수록 가치가 크다.
2. **필터·정렬에 애드센스 상태 추가** — 기존 플랫폼 필터 옆에 배치.
3. **대시보드 위젯 "애드센스 준비 현황"** — 상태별 개수 + 조치가 필요한 블로그
   (필수페이지 미생성 / NEEDS_ATTENTION) 바로가기.
4. **"지금 상태 확인" 버튼** — 정기 동기화를 기다리지 않고 즉시 조회.

### 4.4 승인/미승인 이분 표시에 대해
사용자 제안은 "승인 / 미승인" 2단계였으나, **4단계를 그대로 노출**할 것을 권한다.
- 미신청과 심사중은 **해야 할 일이 완전히 다르다**(필수페이지 생성 vs 대기).
- 2단계로 합치면 "왜 아직 미승인인지"를 알 수 없어 블로그마다 다시 열어봐야 한다.
- 다만 색은 승인=초록 / 나머지=비초록으로 구분해 **한눈에는 이분 인지**가 되게 한다.

## 5. 검색 노출 개선 (2026-08-23 통합)

실측·정책 조사 근거는 [[search_visibility_plan]] 참조. 결론만 옮긴다.

### 5.1 실측으로 확인된 것
- **차단형 문제는 없다** — robots.txt 허용, noindex 없음, canonical·title·description 정상,
  블로거 사이트맵은 당일 반영. `blogs.seo_config`도 워드프레스 5곳 auto_seo 활성.
- **워드프레스 사이트맵이 8/20에서 멈춰** 8/22 발행분(5092) 누락. 구글은 2023년 사이트맵 ping을
  폐지하고 **lastmod를 크롤 스케줄 신호**로 쓰므로 사이트맵 지연 = 발견 지연.
- **URL에 키워드 없음** — 워드프레스는 퍼머링크가 글번호 구조(우리는 이미 slug를 전송 중이나
  구조상 반영 안 됨), 블로거는 한글 제목이라 `blog-post_N`.
- **색인 알림 수단 전무**, **제목 중복 639건**, **서브도메인은 별개 사이트 취급**.

### 5.2 검색엔진 정책 (2026-08 기준)
| 엔진 | 즉시 알림 | 비고 |
|---|---|---|
| 구글 | **없음** | sitemap ping 폐지(2023), IndexNow 미지원, Indexing API는 JobPosting/BroadcastEvent 전용 — **일반 글 사용 시 권한 회수** |
| 네이버 | **IndexNow** | + 서치어드바이저 RSS·사이트맵 제출 병행 필요 |
| 빙 | **IndexNow** | 한 곳 제출로 참여 엔진에 공유 |

→ 사용자가 예전에 제거한 **IndexNow가 네이버 수집의 직접 수단**이다.
→ 구글 Indexing API는 **검토 대상에서 제외**(정책 위반).

### 5.3 실행 항목
| # | 항목 | 내용 |
|---|---|---|
| S1 | **IndexNow 재도입** | 발행 성공 직후 URL 1건 제출. 키 파일 유효성 확인, 응답코드·실패 로그, 재시도. 재발행은 내용이 실제로 바뀐 경우만. 블로그별 on/off |
| S2 | **사이트맵 신선도 점검** | 발행 후 일정 시간 뒤 사이트맵 포함 여부 확인 → 누락 지속 시 경고 |
| S3 | 형제 블로그 제목 중복 차단 | **3.5와 동일 항목** — 애드센스 파트에서 처리 |
| S4 | 발행량·품질 게이트 | **3.1~3.3과 동일 축** — 애드센스 자동화가 곧 이 역할 |
| S5 | 블로거 영문 슬러그(선택) | 영문 제목 생성 → 제목 수정 2단계 우회. 실패·중복 게시 위험이 있어 후순위 |
| S6 | **색인 상태 점검 도구** | 발행 URL의 색인 여부를 주기 확인해 블로그별 색인율 표시 |

### 5.4 blogauto가 할 수 없는 것 (사용자 조치)
- 워드프레스 퍼머링크 구조 변경 — **이미 발행된 수천 URL이 깨지므로 신규 블로그부터** 권장
- Yoast 사이트맵 캐시 갱신 설정 점검
- 네이버 서치어드바이저에 **RSS 추가 제출**
- 서브도메인 → 하위 폴더 전환 여부(대공사, 별도 판단)

### 5.5 기대치 — 필요조건이지 충분조건이 아니다
기술적 차단이 없는데 노출이 안 된다면 남는 변수는 **발견 경로**와 **신뢰도**다.
발견 경로는 S1·S2·S6으로 개선할 수 있으나, **구글에는 즉시 색인시킬 공식 수단이 없다.**
수작업 시절에도 노출이 안 됐고 같은 시기 티스토리는 잘 됐다는 사실은 도메인/플랫폼
신뢰도 요인을 강하게 시사한다. 색인이 되어도 순위가 안 나올 수 있음을 전제로 기대치를 잡는다.

**순서 근거**

- 5는 두 과제 공통이며 **승인 성공률에 직접 영향** — 앞쪽에 둔다.
- **6을 7보다 먼저** 둔다. 측정 수단이 없으면 IndexNow 도입 효과를 알 수 없고,
  이전 운영에서 "효과가 없는 것 같아 제거"한 판단이 반복된다.
- 9는 구글 권한 재발급이 필요해 사용자 작업이 끼므로 뒤로 뺀다.
- 11은 발행 실패·중복 게시 위험이 있어 마지막.

## 7. 리스크
- **오판 시 역효과**: 매칭이 틀려 승인된 블로그를 승인 전으로 보면 니치·1일1포가 계속
  유지된다. 자동 전환에는 반드시 **수동 오버라이드**와 전환 이력 로그를 남긴다.
- **NEEDS_ATTENTION**: 승인 취소·정책 위반 가능성. 자동으로 기능을 해제하지 말고
  경고만 띄운 뒤 사용자가 판단하게 한다.
- **OAuth 재발급 부담**: 블로그 수만큼 재인증이 필요. 계정 단위로 한 번만 받아도 되는지
  (여러 블로그가 같은 구글 계정) 사전 확인 필요.
- **도메인 공유 블로그**: `doooit082.com` 계열 4개가 동시에 전환된다. 의도된 동작이나
  사용자에게 사전 고지 필요.
- **하위호환**: `adsense_role` 미지정 모듈은 `always` 로 동작해 기존 플로우에 영향 없음.

### 검색 노출 파트
- **IndexNow 과다 제출**: 중복·과빈도 제출은 무시되거나 역효과가 날 수 있다. 발행 1건당 1회,
  재발행은 내용이 실제로 바뀐 경우만. **이전 운영에서 IndexNow를 제거한 원인을 규명하지 않고
  그대로 재도입하면 같은 결과가 된다** — 응답코드·실패를 반드시 기록한다.
- **URL 변경**: 이미 색인된 주소를 바꾸면 기존 노출을 잃는다. 신규 발행분만 적용.
- **블로거 2단계 슬러그**: 게시 후 제목을 바꾸는 방식이라 발행 실패·중복 게시 위험. 멱등 처리 필수.
- **효과 측정 부재**: S6 없이 S1만 넣으면 개선 여부를 알 수 없다(순서 6→7을 지킬 것).
- **구글 Indexing API 금지**: 일반 글에 사용하면 정책 위반이며 권한 회수 대상. 코드에 넣지 않는다.
