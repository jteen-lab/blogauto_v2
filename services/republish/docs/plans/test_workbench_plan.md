## 1. 무엇을 만드나

**모듈을 올려놓고 한 번 돌려본 뒤, 결과를 보고 반영할지 버릴지 정하는 화면**
입니다. 이름은 **작업대**로 부르겠습니다.

두 가지로 씁니다.

- **기능이 도는지 확인할 때** — 결과만 보고 버립니다
- **글을 직접 만들어 발행할 때** — 결과를 반영합니다

---

## 2. 왜 필요한가 — 지금 겪는 문제 셋

### 2-1. 확인하려면 실제 운영을 건드려야 한다

새 기능이 도는지 보려면 지금은 이렇게 해야 합니다.

> 모듈에 기능 켜기 → 플로우에 모듈 넣기 → 블로그 연결 → 성장 프로파일 등록
> → 오토런 돌리기

**운영 중인 블로그에 영향이 갑니다.** 스케줄이 잡혀 있어 원치 않는 시점에
글이 나갈 수도 있습니다.

### 2-2. 결과가 기존 데이터와 섞인다

제목을 수집하면 **기존 임시 제목 더미에 섞여 들어갑니다.** 이번 회차가 무엇을
만들었는지 골라내기 어렵습니다.

### 2-3. 일부만 보여줘서 판별이 안 된다

실행 기록에는 몇 줄만 남습니다. **"12건 수집"이라고 떠도 그게 전부인지, 뭔가
걸러진 건지, 아예 동작을 안 한 건지 알 수 없습니다.**

## 3. 화면 구성

```
┌─ 구성 ──────────┬─ 실행과 결과 ──────┬─ 미리보기 ────┐
│ 블로그 선택      │  단계 1 · 키워드     │              │
│                │   [실행]            │  실제 스타일이  │
│ 모듈 담기        │   결과 40건 표시     │  적용된 모습   │
│  · 키워드        │   ☑ 3건 선택        │              │
│  · 제목          │   [다음 단계로]      │  커버 이미지   │
│  · 글 생성       │                    │  버튼·고지문   │
│                │  단계 2 · 제목       │              │
│ 기능 단독 담기    │   [실행]            │  HTML 보기    │
│  · 지식인 수집    │   결과 15건 표시     │  복사 버튼    │
│  · AI 흔적 검사   │                    │              │
│                │  [전체 실행]         │  [반영] [폐기] │
└────────────────┴────────────────────┴───────────────┘
```

**왼쪽에서 담고, 가운데서 돌리고, 오른쪽에서 확인합니다.**

기존 플로우 화면과 조작이 같습니다. 다른 점은 **오토런에 등록하는 대신 실행
버튼을 누른다**는 것과, **반영을 누르기 전에는 아무것도 남지 않는다**는 것뿐
입니다.

---

## 4. 동작 시나리오

### 4-1. 기능이 도는지 확인할 때

> 지식인 수집을 새로 넣었는데 실제로 상황이 잡히는지 보고 싶다

1. 작업대를 연다
2. **키워드 모듈**을 담고 지식인 수집을 켠다
3. 블로그를 고른다
4. **[실행]**
5. 수집된 질문과 거기서 뽑힌 조건이 **전량** 뜬다
6. 확인만 하고 **[폐기]** — 아무것도 남지 않는다

**운영 데이터가 전혀 건드려지지 않습니다.**

### 4-2. 글을 만들어 발행할 때

> 이사 견적 니치로 한 편 써서 올리고 싶다

1. 프리셋 **「이사노트 수동 생성」**을 불러온다
2. 왼쪽 소스 패널에서 **지식인·카페 질문을 검색**한다
3. 마음에 드는 질문을 고른다
4. **[실행]** — 쟁점·검색·구조·본문이 순서대로 채워진다
5. 오른쪽에서 실제 모습을 본다. 마음에 안 들면 본문을 고친다
6. **[반영 → 발행대기글로 저장]** 또는 **[반영 → 즉시 발행]**

---

## 5. 결과는 전부 보여줍니다

**이 화면의 핵심입니다.** 만들어진 것을 하나도 빠뜨리지 않고, **걸러진 것은
왜 걸러졌는지와 함께** 보여줍니다.

```
수집 52건
  ├ 니치 무관으로 제외    8건
  ├ 이미 있는 것으로 제외  4건
  └ 남은 것             40건

   [전체 52]  [채택 40]  [제외 12]     ← 눌러서 각각 확인
```

**이게 있어야 "누락인지 미동작인지"가 판별됩니다.** 12건이 걸러진 걸 보면
필터가 도는 것이고, 52건이 0건이 되면 필터가 과하다는 뜻입니다.

**표시 규칙**

- 각 항목은 **어느 소스에서 왔는지** 표시합니다
- 제외된 항목은 **사유**를 함께 적습니다
- 정렬·검색이 됩니다 (건수가 많을 때)
- 각 항목에 **체크박스**가 있습니다

---

## 6. 골라서 다음 단계로 넘깁니다

한 번에 끝까지 돌리는 것도 되지만, **단계마다 끊어서 고를 수 있어야** 합니다.

```
키워드 수집  → 40건 중 3건 선택 →
제목 생성    → 15건 중 2건 선택 →
글 생성      → 2편 확인        →
반영
```

**고르지 않은 것은 다음 단계로 가지 않습니다.** 그래서 기존 데이터와 섞이지
않고, 이번에 만든 것만 끝까지 따라갑니다.

**되돌아가기**도 됩니다. 제목이 마음에 안 들면 키워드 선택으로 돌아가 다시
고르고 재실행합니다.

---

## 7. 반영은 모듈마다 다릅니다

**화면에 무엇을 올렸느냐에 따라 반영 버튼이 하는 일이 달라집니다.**

| 올린 것 | 결과물 | 반영하면 |
|---|---|---|
| 키워드 | 키워드 후보 | 고른 것만 **키워드 풀에 채택** |
| 제목 생성·수집 | 제목 | 고른 것만 **제목 재고에 투입** |
| 제목 이관 | 이관 대상 | 고른 것만 **정식 제목으로 이동** |
| 글 생성 | 제목·본문·이미지 | **발행대기글 저장** 또는 **즉시 발행** |
| 수집 | 글·주소 | 고른 것만 **수집함에 저장** |

**여러 단계를 돌렸으면 반영 버튼도 단계마다 따로** 뜹니다. 키워드만 반영하고
글은 버리는 것이 가능해야 합니다.

**용어는 이렇게 통일합니다.**

- **[반영]** — 실제 데이터에 넣습니다
- **[폐기]** — 아무것도 남기지 않습니다
- **[다음 단계로]** — 고른 것을 다음 모듈로 넘깁니다

---

## 8. 테스트와 수동 작업을 가릅니다

| | 테스트 | 수동 작업 |
|---|---|---|
| 목적 | 기능 확인 | 실제 글 제작 |
| 횟수 | 1회~수회 | 반복 |
| 구성 | **저장 안 함** — 그때그때 담음 | **프리셋으로 저장** |
| 결과 | 대개 폐기 | 반영 |

**프리셋은 구성만 저장합니다.** 어떤 모듈을 어떤 순서로 담았는지, 어느 블로그
를 쓰는지까지입니다. **결과물은 저장되지 않습니다.**

**기능 단독 담기**도 됩니다. 모듈 전체가 아니라 **지식인 수집만**, **AI 흔적
검사만** 골라 담을 수 있습니다.

---

## 9. 안전장치

### 9-1. 실제 발행과 같은 길로 돌립니다

**결정 사항입니다.** 작업대의 글 생성은 오토런이 실제로 쓰는 그 길을 그대로
탑니다. 별도 테스트 장치를 쓰면 **실제와 다른 코드를 검증**하게 되고, 그게
지금 겪는 문제의 원인입니다.

> **실증**: 어제 넣은 프롬프트 로테이션은 실제 발행 길에만 붙어 있어, 현재
> 모듈 테스트 버튼으로는 변형을 3개 넣어도 매번 같은 구조가 나옵니다.

**운영 경로를 건드리는 만큼 이렇게 합니다.**

- 평소에는 **아무것도 달라지지 않습니다.** 테스트 표시가 켜졌을 때만 다르게 돕니다
- 배포 전 **기존 자동 발행이 정상인지 먼저 확인**합니다
- 테스트 표시가 켜지면 **실행 기록과 통계를 남기지 않습니다.** 다른 플로우
  성공률이 오염되지 않습니다

### 9-2. 되돌릴 수 없는 것은 뺍니다

**문의폼 생성**과 **재발행**은 작업대에서 제외합니다. 누르는 즉시 외부 서비스
나 실제 블로그 글에 반영되고 되돌릴 방법이 없습니다.

### 9-3. 발행은 두 번 확인합니다

즉시 발행은 되돌릴 수 없으므로 **반영 → 발행 방식 선택 → 최종 확인** 순으로
갑니다. 기본값은 **발행대기글 저장**입니다.

### 9-4. 대기열을 타지 않습니다

작업대 실행은 백그라운드 대기열로 넘기지 않고 **그 자리에서 끝까지 돌립니다.**
대기열로 가면 결과를 화면에서 볼 수 없습니다.

## 10. 작업 단계

| 단계 | 내용 | 결과 |
|---|---|---|
| **1** | 저장 없이 한 번 돌리는 기반 | 모듈을 담아 실행하면 결과가 뜨고, 아무것도 안 남음 |
| **2** | 결과 전량 표시 | 걸러진 것과 사유까지 보임 |
| **3** | 골라서 다음 단계로 | 단계 연결이 됨 |
| **4** | 소스 수집 패널 | 지식인·카페에서 질문을 찾아 시작 |
| **5** | 미리보기와 편집 | 실제 모습 확인, 본문 수정 |
| **6** | 모듈별 반영 | 채택·투입·저장·발행 |
| **7** | 프리셋 | 자주 쓰는 구성 저장·불러오기 |

**1단계가 끝나면 이미 쓸 만합니다.** 2·3단계가 "확인이 안 된다"는 문제를
풀고, 4~6단계가 수동 작업을 자동화합니다.

## 11. 구현 메모

> 이 절만 코드 식별자를 씁니다.

**기반**: `flow_scheduler.execute_flow_now()`(630행)에 모든 모듈 타입 디스패치
가 이미 있으나 **호출처가 없습니다(고아 함수)**. 여기에 `flow` 객체 주입과
`dry_run` 인자를 추가해 진입점으로 씁니다.

**휘발 실행**: DB에 Flow를 만들지 않고 메모리에서 조립한 객체를 주입합니다.
`_get_flow_with_modules()` 호출을 `flow or ...` 로 바꾸는 수준입니다.

**부작용 차단**: `_save_autorun_log()` 와 `state.record_execution()` 두 곳만
`dry_run` 에서 건너뜁니다.

**모듈별 dry_run**: `title_gen/runner.py`·`keyword_lab/title_maker.py`·
`title_gate.py`·`title_collect/workbench.py` 는 이미 지원합니다.
`FlowGenerateExecutor` 에 신규 추가가 필요하며, `pipeline_full_tester.py` 는
쓰지 않습니다(§9-1).

**동기 실행**: `_use_celery()` 분기를 테스트에서 우회합니다.

**소스 수집**: `keyword_lab/sources/community.py` 의 `collect_questions()` 를
그대로 씁니다.

**미리보기**: `SubstitutionProcessor._markdown_to_html()` + 블로그
`style_config` 를 iframe 에 주입합니다.

**제외 대상**: `contact_form`, `republish`.

**파일 크기**: `flow_scheduler.py` 가 4,564줄입니다. 신규 로직은 별도 모듈로
분리하고 이 파일에는 인자 추가와 분기 두 곳만 넣습니다.

## 12. 리스크

**운영 발행 경로 수정** — 가장 큰 위험입니다. 테스트 표시가 꺼진 평소 동작이
바뀌지 않는지 배포 전에 확인합니다. 단계 1을 배포한 뒤 **실제 자동 발행이
한 차례 정상 동작하는 것을 보고** 다음으로 갑니다.

**결과 건수가 많을 때** — 키워드 수집은 수십~수백 건이 나옵니다. 전량 표시가
화면을 무겁게 할 수 있어 묶어서 보여주고 펼치는 방식이 필요합니다.

**중간 편집 후 재실행** — 본문을 고친 뒤 이미지만 다시 만드는 식의 부분 재실행
은 단계 간 의존을 잘 정리해야 합니다. 단계 5에서 다룹니다.

**발행 사고** — 테스트하려다 실제 발행이 나가는 것이 최악입니다. 기본값을
발행대기글로 두고, 즉시 발행은 확인을 한 번 더 받습니다.

## 구현 형태

| 계획 | 구현 |
|---|---|
| 저장 없이 한 번 돌리기 | **리허설 세션** — 실행기의 저장 요청을 보류했다가 마지막에 되돌림. 실행 코드는 무수정 |

| 소스 패널 | 지식iN·카페 검색 + 상황 신호 표시, 상황 있는 질문 우선 정렬 |
| 미리보기 | 블로그 style_config → CSS 변환 주입, 본문 편집 모드, HTML 복사 |
| 반영 | 키워드=풀 채택 · 제목=재고 관문 투입 · 글=발행대기글 저장/즉시 발행(확인창) |
| 프리셋 | 구성만 시스템 설정에 JSON 저장(최대 50개), 결과물 미저장 |
| 제외 | 문의폼·재발행은 실행 요청 자체를 거부 |

# 명칭·화면 개편 (2026-09-14)

**「작업대」 → 「모듈 테스터」** 로 바꿨습니다. 수집 화면에 이미 **「제목
작업대」** 가 있어 이름이 겹쳤습니다. 주소도 `/module-tester` 로 옮기고
옛 주소는 그쪽으로 넘깁니다.

## 화면을 다른 페이지와 통일

| 항목 | 맞춘 대상 |
|---|---|
| 폭 | 플로우·모듈·블로그 목록과 같은 폭 |
| 제목·추가 버튼 | 우측 상단 테두리 버튼, 모바일 플로팅 버튼 |
| 요약줄 | 목록 화면의 회색 컨트롤 바 |
| 하단 시트 | 플로우의 모듈·블로그 선택 시트와 같은 규격 |
| 버튼 | 공통 버튼 클래스 |

## 조작 방식 변경

- 드롭다운을 없앴습니다. **블로그 추가 · 모듈 추가** 버튼을 누르면
  하단 시트가 올라와 고릅니다
- 담긴 블로그·모듈은 **상단 요약줄에 칩**으로 보입니다. 칩에서 바로 뺍니다
- 화면을 나누지 않고 **가운데 한 줄기**로 단계가 이어집니다
- 소스 검색도 하단 시트로 들어갔습니다. 고른 질문은 칩으로 남습니다
- **미리보기는 결과 항목의 버튼**을 누르면 하단 시트가 확장됩니다.
  오른쪽 고정 영역을 없앴습니다

돌고, 결과 목록에 블로그 이름이 함께 붙습니다. 글 생성은 회차당 3편
