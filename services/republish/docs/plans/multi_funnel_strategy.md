# 다단계 유입 퍼널 전략 검토 (2026-08-24)

> 상태: 조사 완료 · 논의용 (미확정 · 미구현)
> 관련 [[monetization_strategy_2026]] [[niche_title_aeo_plan]]

## 1. 사용자 구상 (정리)

**배경**: 애드센스 2개월 반려. 원인은 70~80% 품질 볼륨 전략이 강화된 승인 기준을
따라가지 못한 것으로 판단. 게이트 추가·고단가 니치 정리는 착수 완료.

**문제**: 오가닉만으로는 수익까지 시간이 너무 길다 → **외부 유입** 필요.

**구상한 퍼널**:
```
네이버 블로그(정보 정리·유입)
   → 워드프레스/블로거(상세 설명 · 애드센스)
      → CPA 랜딩(상담·DB 전환)
```
- CPA 랜딩은 Astro + Cloudflare Pages 단독 사이트(가볍고 유지비 0)
- 생성 방식 변경: **같은 제목으로 네이버용/블로그용/CPA용을 동시 생성 → 각 플랫폼
  발행 후 상호 연동**
- 쿠팡파트너스는 탈퇴 상태, 재개 계획 없음

## 2. ⚠️ 치명적 제약 — 자동 발행이 막힌 플랫폼

이 구상의 1단계가 성립하지 않는다. 먼저 확인해야 한다.

| 플랫폼 | 글쓰기 API | 상태 |
|---|---|---|
| **네이버 블로그** | `openapi.naver.com/blog/writePost.json` | **2020-05-06 종료** |
| **티스토리** | Open API | **2024-02 종료** |
| 워드프레스 | REST API | ✅ 사용 중 |
| 블로거 | Blogger API v3 | ✅ 사용 중 |

**네이버가 API를 닫은 사유가 정확히 이 용법이다**:
> "자동화 프로그램을 이용한 대량의 유사 콘텐츠 반복 발행, 제휴마케팅 수수료를
> 노리는 어뷰징 증가, 이용약관·게시물 운영정책 위반"

→ 브라우저 자동화(셀레니움 등)로 우회하는 방법은 존재하나 **약관 위반이며 계정
정지 대상**이다. 네이버 블로그는 저품질/제재가 걸리면 복구가 어렵고, 무엇보다
**애드센스 승인을 받으려는 시점에 정책 위반 이력을 만드는 것은 위험**하다.

**결론**: 네이버 블로그 단계는 **자동화 대상에서 제외**하고, 하려면 **수동 발행**
전제로만 설계해야 한다. blogauto는 "네이버용 원고를 만들어 두는 것"까지만 담당.

## 3. 대안 유입 채널 (자동화 가능한 것)

| 채널 | 자동 발행 | 비고 |
|---|---|---|
| **Threads** | ✅ 공식 API | 게시는 기본 권한으로 가능(검색만 심사 필요) |
| **X(트위터)** | ✅ API | 무료 티어 제한 큼 |
| **Astro + Cloudflare Pages** | ✅ Git push | 정적 사이트, 유지비 0, 속도 우위 |
| 네이버 블로그 | ❌ | 수동만 |
| 티스토리 | ❌ | 수동만 |

**Astro + Cloudflare Pages 검증**: 기본 JS 런타임 0, 엣지 배포로 100ms 이하 응답,
무료 티어 대역폭 무제한. 워드프레스 대비 Core Web Vitals·SEO에서 유리하다는 평가가
일관된다. **CPA 랜딩·원페이지 용도로 적합**하다.

## 4. 퍼널 재설계 (제약 반영)

원안의 3단계를 자동화 가능한 형태로 바꾼다.

```
[A] 소셜 훅 (Threads/X)          — 자동 발행 O
      ↓
[B] 워드프레스/블로거 본문        — 자동 발행 O · 애드센스 수익
      ↓
[C] Astro 랜딩 (CPA/상담)        — 자동 배포 O · 전환 수익

[선택] 네이버 블로그              — 수동 발행. blogauto는 원고만 생산
```

**한 제목 → 3종 산출물**이라는 사용자 아이디어는 유효하다. 다만 각 산출물의
목적이 달라야 한다.

| 산출물 | 길이 | 목적 | 링크 |
|---|---|---|---|
| 소셜 훅 | 200~400자 | 궁금증 유발 | → B |
| 본문 | 2,000자+ | 완결된 답변 + 광고 | → C (해당 시) |
| CPA 랜딩 | 800~1,200자 | 단일 행동 유도 | 폼/전화 |

## 5. ⚠️ 정책 리스크 (반드시 사전 확인)

| 항목 | 리스크 | 대응 |
|---|---|---|
| **애드센스 페이지에 CPA 링크** | 오해 소지 있는 유도·과도한 상업 링크는 정책 위반 소지 | 광고와 콘텐츠 명확히 구분, 유도 문구 절제 |
| **CPA 랜딩에 애드센스** | 콘텐츠 없는 랜딩에 광고 게재는 승인 거부 사유 | 랜딩에는 **애드센스 미게재** 권장 |
| **DB 수집(개인정보)** | 개인정보처리방침·수집 동의 필수 | 필수페이지 모듈 재사용 |
| 네이버 자동 발행 | 약관 위반·계정 정지 | 수동 전환 |
| 저품질 대량 랜딩 | scaled content abuse | 랜딩도 니치별 소수 정예 |

**애드센스 승인 심사 중에는 CPA 링크를 넣지 않는 편이 안전하다.** 승인 후 단계적
도입을 권한다.

## 6. blogauto 반영안 (구현 관점)

### F1. 다중 산출물 생성 (한 제목 → N 산출물)
- 현재: 제목 1개 → 본문 1개 → 블로그 1곳 발행
- 변경: 제목 1개 → **산출물 세트**(소셜/본문/랜딩) → 각 채널 발행
- 구현: 프롬프트 모듈에 **산출물 유형** 추가, 생성 결과를 세트로 묶어 저장
- 선행: `CrawledPost`에 세트 식별자(부모 제목 + 유형) 필요

### F2. 채널 커넥터 확장
- 현재: WordPress / Blogger
- 추가: **Threads(공식 API)**, **Astro 저장소(Git push)**
- Astro는 파일 생성 + 커밋/푸시 → Cloudflare가 자동 배포

### F3. 상호 링크 연동
- B 본문 → C 랜딩 링크 자동 삽입(해당 니치일 때만)
- A 소셜 → B 본문 링크
- 구현: 발행 순서 보장(B 먼저 → URL 확보 → A/C에 주입)

### F4. 전환 측정
- CPA는 **전환이 곧 수익**이라 측정이 필수
- 랜딩에 UTM·전환 이벤트 기록 → blogauto 대시보드 집계
- 이게 없으면 어떤 니치가 전환되는지 알 수 없다

## 7. 우선순위 제안

| 순위 | 항목 | 근거 |
|---|---|---|
| 0 | **애드센스 승인 완료까지 현행 유지** | 심사 중 구조 변경은 변수만 늘린다 |
| 1 | 수익 리포트 연동 | 현재 RPM조차 모른다([[monetization_strategy_2026]] 7장) |
| 2 | F2 Astro 커넥터 | 유지비 0, 정적 랜딩은 리스크 낮음 |
| 3 | F1 다중 산출물 | 구조 변경이 커서 승인 후 착수 |
| 4 | F3 상호 링크 | F1·F2 완료 후 |
| 5 | F4 전환 측정 | CPA 본격화 시점 |
| — | 네이버 자동 발행 | **불가 — 수동 전제로만** |

## 8. 벤치마킹에서 확인된 것 / 확인 못 한 것

**확인된 것**
- CPA 퍼널에서 **맞춤 랜딩 도입 시 전환율 200% 상승** 사례(렌탈 업종)
- 한국 DB 수집 주력 채널은 네이버(GFA·파워링크)·카카오 — **유료 광고 기반**
- 정적 사이트(Astro+CF)의 속도·비용 우위는 일관되게 확인

**확인 못 한 것 (추측 금지)**
- "네이버 블로그 → 워드프레스 → CPA" 3단 퍼널로 **수익화한 구체 사례**는
  공개 자료에서 찾지 못했다. 업계 CPA 사례는 대부분 **유료 광고 → 랜딩** 구조다.
- 즉 이 구상은 **검증된 표준 패턴이 아니라 가설**이다. 작게 검증한 뒤 확장할 것.
