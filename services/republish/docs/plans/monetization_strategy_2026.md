# 수익화 전략 재정립 (2026-08-24)

> 작성 2026-08-24 | 상태: 제안 · 논의용

## 1. 기존 전략과 그 붕괴 지점

**기존**: 70~80% 품질 포스트를 대량 생산 → 상위 노출이 아니어도 노출 총량으로 수익 확보(박리다매).

**전제**: "뒷페이지에 있어도 미미한 수익은 난다."

**붕괴**:
- AI 개요 대상 쿼리의 **제로클릭 80~83%**, 정보성 쿼리 CTR **61~65% 감소**
- 퍼블리셔 구글 유입 **전년비 38% 감소**
- **하위 순위의 잔여 트래픽이 가장 먼저 증발** → 박리다매의 분모가 사라진다
- 2026-03 코어 업데이트가 scaled content abuse를 정조준. 편집 감독 없는 대량 발행 사이트
  트래픽 50~80% 감소 사례

**업계 진단**: "볼륨의 시대는 끝났다. 다만 **게으른** 프로그래매틱이 죽은 것이지 전부는 아니다."
살아남은 곳의 공통점은 **품질 게이트를 유지한 사이트**다.

## 2. 방향 전환 — 폐기가 아니라 재조준

blogauto의 자산(수집→생성→발행 파이프라인, 니치 체계, 유사도 게이트)은 그대로 쓴다.
바뀌는 것은 **무엇을 대량으로 만드느냐**다.

| 축 | 기존 | 전환 |
|---|---|---|
| 목표 | 노출 총량 | **클릭할 이유가 있는 페이지 수** |
| 품질 | 70~80% 균일 | **니치 핵심 20%는 95%, 주변부는 유지** |
| 판정 | 발행 건수 | **페이지 RPM × 유효 세션** |
| 노출 | 검색 순위 | 순위 + **AI 인용** |

핵심 문장: **"AI가 요약할 수 있는 글"이 아니라 "사용자가 클릭해서 확인해야 하는 글"**.

## 3. 클릭이 남는 글의 조건 (검색 결과 종합)

AI가 대신 답할 수 있으면 클릭이 사라진다. 대신할 수 없는 것은 다음이다.

| 유형 | AI가 대체 못 하는 이유 | blogauto 적용 |
|---|---|---|
| **최신 수치·요금·조건** | 학습 시점 이후 값은 모름 | 재발행 리뉴얼로 갱신 주기 관리 |
| **비교·선택 판단** | 조건 조합이 개인별로 갈림 | 비교표 필수화(AEO A4) |
| **절차·서류 체크리스트** | 순서·준비물은 확인이 필요 | 프롬프트 규칙화 |
| **실사용 후기·수치** | 1차 경험은 생성 불가 | ⚠️ 현재 불가 — 4장 참조 |
| **지역·업체 실사 정보** | 지역 단위 최신성 | 지역/업체정보 니치 활용 |

## 4. 정직한 한계 — 자동 생성으로 못 하는 것

**1차 경험은 만들 수 없다.** "직접 써봤다"는 글을 AI로 지어내면 그것이 곧
scaled content abuse이자 신뢰 훼손이다. 이 영역은 **사람이 개입하거나 포기**해야 한다.

따라서 blogauto의 승부처는 **경험담이 아니라 "정리의 밀도"** 다.
- 흩어진 조건을 한 표로 모으기
- 예외·함정을 빠짐없이 적기
- 수치를 최신으로 유지하기
이건 자동화로 가능하고, 사람이 하기엔 품이 많이 든다.

## 5. 실행 제안 — blogauto 기준

### M1. 품질 이원화 (핵심 20% / 주변 80%)
- **핵심 글**: 니치의 돈 되는 질문(대출 한도·보험 비교·세금 계산 등).
  정보이득 + AEO 전부 켜고, 글자수 상향, 비교표·FAQ 필수.
- **주변 글**: 핵심 글로 유입을 보내는 롱테일. 현행 품질 유지.
- 구현: 프롬프트 모듈을 **핵심용/주변용 2종**으로 나누고 제목 재고를 축으로 분리.
  → 이미 만든 `adsense_role`·니치 강제와 같은 구조로 확장 가능.

### M2. 갱신 주기 관리 (최신성이 곧 클릭 이유)
- 요금·금리·지원금은 **수치가 바뀌면 기존 글이 곧 신선한 글**이 된다.
- 이미 있는 **재발행 리뉴얼**을 니치별 주기로 운영(예: 금융 30일, 정부지원금 60일).
- 구현: 리뉴얼 대상 선정에 **니치별 주기** 적용(현재는 블로그 단위).

### M3. 내부링크 허브 구조
- 세분화된 하위주제가 생겼으므로 **주제 클러스터**를 만들 수 있다.
  (예: 신용대출 → 한도/금리/서류/거절사유 상호 링크)
- 체류시간·세션당 페이지뷰가 오르면 **RPM이 직접 상승**한다.
- 구현: 내부링크 모듈이 이미 있음 → **같은 하위주제 우선** 규칙 추가.

### M4. 광고 배치 최적화 (코드 밖 작업이지만 효과 큼)
- 본문 첫 문단 직후·2~3단락 뒤가 클릭률 최고
- 3~5개 유지, 336×280 + 모바일 고정형
- viewability와 CPM은 강한 상관 → **화면에 실제로 보이는 위치**가 핵심
- blogauto가 할 일: **본문 HTML에 광고 슬롯 위치 표식** 삽입(선택)

### M5. 니치 단가 재배치 (이미 착수)
- 생활정보 RPM $3~12 → 금융·보험 $20~80
- 니치 전속 배정으로 **같은 노출에서 수익 3~10배** 차이
- 선행: 신규 니치 제목 재고 확보(수집 스케줄에 위임됨)

### M6. 수익원 다각화 (애드센스 단일 의존 탈피)
- 제휴(쿠팡파트너스 등)는 **승인 전 징검다리**이자 애드센스와 병행 가능
- 수수료 최대 3%, 24시간 쿠키 → **구매 의도 높은 글**에서만 의미
- blogauto 적용: 제품·비교형 글에 제휴 링크 자동 삽입(치환 기능 활용)
- ⚠️ 애드센스 정책과 충돌하지 않게 배치·표기(광고 표시 의무) 확인 필요

## 6. 측정 없이는 전부 추측이다

현재 blogauto는 **발행 건수만** 안다. 수익 판단에 필요한 것은 다음이다.

| 지표 | 출처 | 상태 |
|---|---|---|
| 페이지 RPM·수익 | AdSense API(이미 연동) | **조회 가능 — 미구현** |
| 색인 여부 | 검색엔진 | 계획서 S6 |
| 세션·체류시간 | GA4 | 미연동 |

**최우선 제안**: 애드센스 계정 연동이 끝났으므로 **니치별·블로그별 수익 리포트**를
가져와 대시보드에 붙인다. 그래야 "어떤 니치가 돈이 되는지"를 추측이 아니라
데이터로 판단할 수 있다.

## 7. 우선순위 제안

| 순위 | 항목 | 근거 |
|---|---|---|
| 1 | **수익 리포트 연동** | 측정 없이는 나머지 판단 불가. API 이미 연결됨 |
| 2 | M3 내부링크 허브 | RPM 직접 상승, 구현 비용 낮음 |

| 4 | M2 갱신 주기 | 기존 자산(재발행)을 최신성 무기로 전환 |
| 5 | M5 니치 재배치 | 재고 확보 후 |
| 6 | M6 제휴 병행 | 정책 검토 후 |
