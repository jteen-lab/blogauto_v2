### 1.1 5번 항목이 왜 위험한가 (가장 중요)

**(1) AdSense를 앱에 넣는 것 자체가 금지**
> "Google ads may not be integrated into a software application of any kind, including toolbars (this does not apply to AdMob)."

AdSense for content(AFC)는 모든 WebView 기술에서 지원되지 않는다. 공식 경로는 **AdMob SDK + WebView API for Ads로 WebView 인스턴스를 등록**하는 것뿐이다. 워프/블로그스팟 페이지를 웹뷰로 감싸 애드센스를 그대로 노출시키는 방식은 **정책 위반이며, 애드센스 계정 전체가 위험**해진다.

**(2) Play 스토어 최소 기능 정책(4.3)에 걸림**
단순히 웹사이트를 미러링하는 raw WebView 앱은 거부 대상이다. 2024년부터 구글이 wrapper-only 앱을 대량 정리 중이며, 통과하려면 PWA+TWA 또는 네이티브 기능 추가가 필요하다.

**(3) "무한 푸시알림"은 스팸 정책 대상**

→ **결론: 구현하지 않는다.** 강사가 안 알려주는 이유가 "비싼 정보라서"가 아니라 **가르치면 수강생 계정이 날아가기 때문**일 가능성이 높다.

## 5. ⭐ 핵심 기회: 구글 디스커버

### 5.1 왜 우리에게 맞는가

사용자의 현재 문제는 "**워드프레스/블로거의 단순 오가닉 유입이 당장 힘들다**"는 것이다. 디스커버는:

- **검색 순위 경쟁 없이** 유입이 발생하는 유일한 구글 채널 (피드 노출)
- 공식적으로 **최소 사이트 규모·도메인 권위 요건이 없다**. 주제 단위로 평가하므로 소규모·전문 사이트도 노출 가능
- 제로클릭 문제의 영향을 덜 받음 (피드에서 직접 클릭)
- blogauto가 이미 가진 기능으로 요건의 절반 이상을 자동 충족시킬 수 있음

### 5.2 요건과 blogauto 대응 가능성

| 디스커버 요건 | blogauto 대응 |
|---------------|---------------|
| 대표 이미지 **가로 1,200px 이상** | ✅ 이미지 생성 기능 보유 → **규격 강제만 하면 됨** |
| `max-image-preview:large` 메타 태그 | ⚠️ 워프/블로거 발행 시 삽입 확인 필요 |
| **명시적 저자 바이라인 + 검증 가능한 이력** | ⚠️ 필수페이지 모듈에 저자 정보는 있으나 **글 단위 바이라인은 미구현** |
| 원본성·1인칭 경험·독자 데이터·출처 명시 | ⚠️ 프롬프트 구조 개선 필요 (양→질 전환과 동일 방향) |
| 정확한 제목 (클릭베이트 감점) | ✅ 제목 생성 규칙에 반영 가능 |
| 모바일 Core Web Vitals | ⚠️ 테마 영역 — 가이드 제공 |
| 시의성 | ⚠️ 수집 모듈이 시의성 주제를 우선 잡도록 조정 가능 |

**2026-02 디스커버 코어 업데이트로 E-E-A-T 요건이 강화**됐다. 전문성·권위를 못 보이면 피드에서 사라진다. 즉 디스커버는 "양산 우회로"가 아니라 **질 전환의 보상**이다 — 우리가 이미 가려는 방향과 정확히 같다.

## 7. 우선순위 제안

```
X0 유입 추적 기반        ← 여전히 선행 (무엇이 효과 있는지 측정)
  └ X5 디스커버 대응 세트  ← 신규 최우선. 오가닉 부진의 우회로이자 질 전환의 보상
      └ N2 YMYL 신뢰 신호 (X5 ③과 통합 구현)
X1 외부링크 rel/vignette 정책
N5 승인 전용 블로그 프리셋  ← 승인 급하면 X5보다 먼저
N1 니치 축소               ← 사용자 일정(제목 수집 후)
X2 핀터레스트 / X3 네이버 발행팩
N6 고CPC 태깅 / N7 테마 가이드 (문서)
```
