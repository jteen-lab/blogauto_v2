# 프롬프트 빌더 니치 재구성 (2026-08-28)

> 사용자 방침 변경: 여러 니치를 섞어 쓰던 운영을 **니치 특화 블로그**로 전환.
> 애드센스 승인·검색 노출 모두 특정 니치를 깊게 다루는 쪽이 유리하다는 판단.

## 1. 전수 조사 결과

### 1.1 기존 프리셋의 추천 니치가 실제 카테고리와 불일치

기존 10개 프리셋의 `categories` 표기는 **현재 체계에 존재하지 않는 옛 분류**였다.

| 기존 표기 | 현재 카테고리 |
|---|---|
| 패션 · 뷰티 · 쇼핑 · 직구 | ❌ 패션·뷰티·직구 없음 |
| 문화 · 영화 · 드라마 · 책 | ❌ 전부 없음 |
| 라이프 · 인테리어 · 홈가전 · 반려동물 | ❌ 인테리어·반려동물 없음 |
| 육아 · 교육 · 자격증 · 어학 | ⚠️ 어학 없음 |

반대로 **재고가 있는데 프리셋이 없는 니치**도 있었다:
정부지원금/복지(54) · 보험(36) · 세금/절세(15) · 시니어/노후(10) · 지역/업체정보(15).

### 1.3 기존 블록으로 못 쓰는 성격

- 정부지원금·자격증처럼 **자격 요건 → 서류 → 절차 → 기한**이 핵심인 글에 맞는 패턴이 없었다
  (P1~P5는 정보·교육·가이드·분석·경험형).
- YMYL 서술 원칙이 없었다. 구글은 돈·건강 주제에 더 엄격한 기준을 적용한다.

## 2. 반영한 최신 프롬프트 기법

| 기법 | 반영 |
|---|---|
| **역할 기반 프롬프팅** — 작업 전에 모델의 참조 틀을 좁힌다 | 페르소나 축이 이미 담당. `P-Guide`(실무 안내자) 추가로 절차형 보강 |
| **목표를 명시** — 모호하면 산출도 모호 | 시작 톤 `T-Eligibility`가 첫 문단의 목적을 못박음 |
| **YMYL: 자격·출처·면책·갱신일** | `C-YMYL` 원칙 블록 신설 |
| **한 번에 한 과제** | 기존 구조 약속이 담당 |
| 프롬프트 캐싱을 위한 정적→가변 순서 | **미반영 — §5 제안** |

## 5. 구현 중 발견한 결함 — 시드가 신규 블록을 넣지 않았다

`ensure_seeded()`가 **"해당 타입에 행이 하나도 없을 때만"** 시드했다.
이미 시드된 운영 DB에서는 **새 블록이 영원히 들어가지 않는다.**
프리셋이 존재하지 않는 코드를 가리켜 프롬프트가 조용히 깨졌을 상황이었다.

→ **코드 단위 멱등 시드**로 변경(없는 코드만 추가, 운영자가 고친 본문은 보존).
회귀 테스트 3건으로 고정.

## 6. 남은 제안 — 프롬프트 캐싱 순서

최신 권고는 **정적 내용을 앞, 가변 내용을 뒤**에 두라는 것이다(프리픽스 캐시 적중).
현재 우리 템플릿은 반대다:

```
제목/카테고리/키워드 (가변)   ← 맨 앞
지시문 블록들 (정적)          ← 뒤
```

뒤집으면 모든 글이 동일 프리픽스를 공유해 캐시 적중률이 오른다(비용·지연 감소).
다만 **순서가 바뀌면 모델 출력이 달라질 수 있어** 일괄 적용 전 A/B 확인이 필요하다.
이번 작업에는 넣지 않았다.
