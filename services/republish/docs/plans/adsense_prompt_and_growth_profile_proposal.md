# 애드센스 승인용 프롬프트 + 성장 프로파일 제안 (보고서, 미적용)

> **상태**: 제안·검토 대기 — **코드/블로그오토 설정에 미적용**.
> **목적**: 사용자 요청에 따라 (1) 현재 blogauto 생성 프롬프트를 기준으로
> 애드센스 승인용 프롬프트를, (2) 그에 맞춰 운영할 블로그의 성장 프로파일
> 템플릿을 설계해 보고한다. 실제 적용(코드 반영)은 사용자 검토 후 별도 진행.
> 근거: `docs/plans/adsense_approval_features_plan.md` F7(Information Gain
> 프롬프트 개편), F4(니치 강제), F5(케이던스), F9(준비도 감사).

---

## 1. 현재 프롬프트 구조 (기준선)

`app/services/prompt_builder/blocks.py`가 단일 출처(SoT). 운영자가
`/prompt-builder`에서 4개 축(페르소나 6종·독자수준 3종·섹션패턴 5종·
시작톤 5종)을 골라 `build_prompt()`가 `user_prompt_template`을 조립한다.
공통 규칙(`COMMONS`, 4종 중 택1)과 고정 `STRUCTURE`(STEP1~4, 표 2회·목록
2회 강제, 총 1600자+)는 모든 조합에 공통으로 붙는다.

이 구조 자체(문체·난이도·섹션 순서 다양화)는 애드센스와 무관하게 유지해도
된다 — 문제는 **정리형 패턴이 "공개 정보 재배열"에 머물기 쉽다는 점**
(계획서 §1 반려진단 4번, Information Redundancy)이다.

---

## 2. 애드센스 승인용 프롬프트 — 설계

### 2.1 방향

기존 4축 시스템을 갈아엎지 않고, **5번째 고정 지시문 블록
("정보이득 지시문")을 STRUCTURE 앞에 추가**하는 방식을 제안한다.
이렇게 하면:
- 기존 니치별 페르소나/패턴 다양성(블로그별 문체 차별화)을 그대로 유지.
- 애드센스 승인이 필요한 블로그에만 옵트인 가능(F2 저자성 주입과 동일한
  "옵트인 → 기존 운영 블로그 영향 없음" 패턴).
- `blocks.py`에 `COMMONS`처럼 선택 가능한 블록으로 추가하면 프리셋
  조합에도 자연스럽게 낄 수 있음.

### 2.2 지시문 블록 초안 (신규, 가칭 `Q-AdsenseGain`)

```
✦ 정보이득 지시문 (애드센스 승인 대비)
- 공개된 정보를 그대로 재배열/요약만 하지 말 것. 각 섹션에 아래 중 최소
  1개 이상 포함:
  (a) 서로 다른 조건/상황을 비교한 구체적 판단 기준
  (b) 실제 적용 시 흔히 놓치는 주의점·예외 상황
  (c) 수치·기간·조건 등 검증 가능한 구체 정보(예: "2026년 기준",
      "3개월 이상 유지 시")
- 표·목록은 정보 나열이 아니라 "무엇을 고를지 판단하는 근거"가 드러나게
  구성 (예: 단순 스펙 나열 대신 "이런 경우엔 A, 저런 경우엔 B")
- 가능한 경우 한 문장 이상 출처를 명시 (예: "OO 기관 발표에 따르면",
  "OO 공식 안내 기준으로"). 없는 통계·수치를 지어내지 말 것 — 확인 불가
  시 정성적 표현으로 대체
- 뻔한 결론/광고성 마무리 문구("꼭 확인해보세요!" 같은 공허한 CTA) 지양,
  실행 가능한 다음 행동 하나로 마무리
```

### 2.3 완성 프롬프트 예시 (전문가·중급·P1·수치 프리셋 + 애드센스 지시문)

```
제목: {title}
카테고리: {category}
키워드: {keywords}

────────────────────────────────────────
✦ 글쓰기 페르소나 — 전문가 설명체
- "~합니다", "~됩니다", "~로 나타납니다" 격식 종결
- 전문 용어는 그대로 사용, 필요시 한 줄 보충
- 수치·근거·비교 적극 활용, 감정 표현·감탄사 최소화
- 평가는 비교 우위 형식으로 표현 ("A 가 B 대비 ~ 우위")
────────────────────────────────────────

────────────────────────────────────────
✦ 독자 수준 — 중급자
(...기존과 동일...)
────────────────────────────────────────

────────────────────────────────────────
✦ 글쓰기 기본 원칙
(...기존 COMMONS 그대로...)
────────────────────────────────────────

────────────────────────────────────────
✦ 정보이득 지시문 (애드센스 승인 대비)
(...2.2의 신규 블록...)
────────────────────────────────────────

────────────────────────────────────────
✦ 구조 — 패턴 P1 (정보·정리형)
(...기존과 동일...)
────────────────────────────────────────

────────────────────────────────────────
✦ 시작 톤 — 현황·수치·문제의식
(...기존과 동일...)
────────────────────────────────────────

────────────────────────────────────────
✦ 구조 약속
(...기존 STRUCTURE 그대로...)
────────────────────────────────────────
```

### 2.4 프리셋 조합 권장 (애드센스 승인 대비 블로그)

정보이득 지시문과 궁합이 좋은 조합 — "근거 제시형" 문체가 출처·비교
지시문과 자연스럽게 맞물림:
- `s1-v1`(전문가·중급·P1·수치), `s1-v2`(분석가·결정·P4·수치)
- P5(경험·공감형) 패턴 + P-Friend/P-Essayist 페르소나 조합도 권장 —
  "직접 경험" 신호가 E-E-A-T에 유리(계획서 §1의 "직접 경험 전무" 지적과
  직결).

### 2.5 적용 방법 제안 (코드 반영 시, 향후)

1. `blocks.py`에 `QUALITY` 블록군 신설(`COMMONS`처럼 리스트), 2.2 문구를
   `Q-AdsenseGain` 코드로 등록.
2. `Blog.adsense_status`(계획서 F5 필드, 미구현) 값이 `preparing` 이상인
   블로그는 `build_prompt()`가 자동으로 이 블록을 삽입 — 운영자가 수동
   선택 안 해도 됨.
3. `adsense_status` 미구현 상태인 지금은 **`/prompt-builder`에 5번째
   선택 블록으로 노출**해 운영자가 애드센스 준비 중인 블로그에서만
   수동으로 골라 쓰는 방식으로 먼저 시작 가능(F4/F5 없이도 독립 적용
   가능한 최소 단위).

## 3. 성장 프로파일 템플릿

계획서 §4(예상 데이터 변경: `niche`, `author_profile`, `adsense_status`,
`publish_daily_cap`)가 아직 부분 구현(author_profile만 완료)이라, F4/F5가
코드로 자동 강제되기 전까지 **운영자가 수동으로 따라갈 체크리스트/필드
템플릿**으로 우선 제안한다. 추후 F4/F5/F9 구현 시 이 템플릿의 필드가
그대로 DB 컬럼·UI로 승격될 수 있게 설계했다.

### 3.1 블로그별 프로파일 필드 (템플릿)

| 필드 | 설명 | 현재 구현 여부 |
|---|---|---|
| `niche` | 단일 주제 문구(예: "생활 금융정보") — 이 범위 밖 글은 이 블로그에 발행하지 않음(운영자 수동 판단) | 미구현(F4) — 수동 준수 |
| `adsense_status` | `none` → `preparing` → `applied` → `approved`/`rejected` | 미구현(F5) — 운영자가 메모/스프레드시트로 추적 |
| `daily_cap` | `preparing` 단계 일 발행 상한(권장 1~2편) | 미구현(F5) — 오토런 발행 수동 조절로 대체 |
| `author_profile` | 이름/소개/전문분야 | **구현됨** — 블로그 설정 "애드센스" 탭에서 바로 입력 가능 |
| `required_pages_status` | 4종 필수 페이지 발행 상태 | **구현됨** — 같은 탭에서 생성 버튼 |
| `prompt_quality_mode` | 위 2장 애드센스 지시문 적용 여부 | 미구현 — 지금은 프롬프트 텍스트 수동 붙여넣기로 대체 가능 |
| `target_post_count` | 신청 전 목표 글 수(권장 20~30) | 없음(수동 카운트) |
| `readiness_checklist` | F9 체크리스트 결과(수동) | 없음(F9 미구현, 3.3 체크리스트로 대체) |

### 3.2 단계별 성장 경로 (제안)

1. **준비기 (착수~1주)**
   - 니치 확정(1개 문구로 고정) → 이후 이 블로그엔 그 범위 글만 등록
   - 필수 페이지 4종 생성(기존 UI 버튼)
   - 저자 프로필 입력(이름 필수, 소개·전문분야 권장)
   - `/prompt-builder`에서 위 2.2 지시문을 프롬프트에 수동 포함
   - 발행 케이던스 1~2편/일로 수동 조절(오토런 발행 수량 설정)

2. **축적기 (1~3주, 목표 20~30편)**
   - 니치 이탈 여부 수동 점검(발행 후 카테고리 확인)
   - 케이던스 유지, 급증 금지
   - 표만 있는 글·600자 미만 글은 F6 게이트가 이번 세션부터 자동 차단
     (배포 완료 시)

3. **신청 전 자가진단 (3.3 체크리스트로 수동 수행)**

4. **신청**

5. **반려 시**: 반려 사유 재확인 → 2~3주 대기 → 미충족 항목 보완 후
   재신청

6. **승인 후**: `daily_cap` 해제(정상 케이던스 복귀), 니치 확장 여부는
   승인된 니치의 성과를 보고 별도 검토

### 3.3 신청 전 수동 체크리스트 (F9 대체, 수동판)

- [ ] 필수 페이지 4종 존재(개인정보처리방침/이용약관/소개/문의)
- [ ] 저자 정보/바이라인 노출(글 하단)
- [ ] 니치 이탈 글 없음(전수 확인 또는 최근 20편 샘플)
- [ ] 총 글 수 ≥ 20~30
- [ ] 600자 미만 글 없음(F6 게이트로 신규 글은 자동 보장, 과거 글은
      수동 확인 필요)
- [ ] 최근 2주 발행 속도가 정상 범위(급증 없음)
- [ ] 출처/근거 문구가 포함된 글 비율 체감상 충분(정량 측정은 F9 대기)

## 4. 요약 — 사용자 확인 필요 사항

- 2장 프롬프트 지시문 문구·프리셋 권장을 승인하면, 다음 세션에
  `blocks.py`에 `Q-AdsenseGain` 블록으로 코드 반영 가능(F7 착수).
- 3장 성장 프로파일은 지금 당장 수동 운영 가능(코드 불필요). 필드를
  실제 DB 컬럼(`niche`/`adsense_status`/`daily_cap`)으로 승격하려면
  F4/F5 착수가 먼저 필요 — 그때 설계 질문(니치 판정 방식, 케이던스
  기본값, 차단 vs 경고) 확정 필요.
- **(2026-08-11 사용자 확정) 실제 검증은 "F7 프롬프트 적용 + 1일1포"가 동시에
  충족된 상태여야 함.** 또한 1일1포를 `growth_profile_defaults.py`의 기존
  3프리셋처럼 사용자가 매번 수동으로 daily_count=1을 맞추게 두지 말고,
  "애드센스 승인용" 프리셋을 신설해 **기본값으로 1일1포를 고정** — F7 착수 시
  이 프리셋에 Q-AdsenseGain 블록도 함께 기본 적용하는 방향으로 묶어서 진행.
  (근거: `docs/plans/adsense_approval_features_plan.md` §9)
