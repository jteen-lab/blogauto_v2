# 모듈 테스터 — 글쓰기 후 발행 반자동화

> 2026-09-15 · 선행 분석 `claudedocs/module_tester_publish_gap_20260915.md`

## 앞선 분석의 정정

발행이 막혀 있다고 본 것은 틀렸다. 블로그에 저장된 인증 토큰이 주
경로이고 계정 항목은 보조였다 — 이사노트를 포함해 블로거 블로그 8개
모두 토큰이 들어 있다. **발행은 손댈 것이 없었다.**

## 한 것

### 1. 홍보 링크 목록

글 끝에 붙일 버튼 하나를 담는다. 이름·주소·버튼 문구·고지문만 있으면
된다. CPA 오퍼(광고 심의 규칙 관리)의 확인 절차를 밟지 않는다.

모듈 테스터의 **링크 추가** 버튼 → 하단 시트에서 고르거나 새로 등록.
고르지 않으면 정보성 글로 조립된다.

특정 블로그 전용으로 둘 수 있다. 오퍼와 이어붙이면 어느 글에서
눌렸는지 추적된다(선택).

### 2. 고지문·버튼 조립

수작업으로 매번 손으로 붙이던 부분이다.

```
고지문 (맨 앞 — 2024-12-01 개정으로 끝부분 게재 불가)
표지 이미지
본문
버튼 (div 로 감싼다 — button-link 는 블록 스타일)
```

**조립은 서버에서 한 번만 한다.** 화면에서 따로 만들면 보이는 것과
올라가는 것이 갈린다. 미리보기와 저장이 같은 결과를 쓴다.

두 번 조립해도 겹치지 않는다. 이미 고지문이 있거나 같은 주소의 버튼이
있으면 넘어간다.

추적값은 글 번호가 나온 뒤에야 만들 수 있어 저장 직후 한 번 갈아
끼운다.

### 3. 이사노트 생성 모듈

수작업의 1인칭 경험담 방식을 프롬프트로 옮겼다. 기존 블로그들은 전문가
설명체(격식·수치·비교)를 쓰지만 이사노트는 겪은 사람이 답하는 글이라
말투와 구조가 다르다.

- 자기 경험을 최소 세 번, 금액·시기와 함께
- 인용문 금지, 참고한 곳 언급 금지
- 먼저 결론 → 갈리는 지점 → 근거 → 사례 → 정리 목록 → 판단
- 상투어 22개 명시 금지
- 근거 체크리스트와 상투어 검사를 켠 상태

한 번만 돌리면 된다:
`python3 scripts/create_isanote_prompt_module.py`

### 4. 미리보기 버튼이 맨몸으로 보이던 문제

버튼 스타일은 블로그마다 `a.button` 으로 저장돼 있는데 글에 붙는
버튼은 `div.button-link` 안의 링크다. 14개 블로그 전부 `.button-link`
규칙이 없어, 미리보기에서만 버튼이 스타일 없이 보였다. 같은 스타일을
양쪽에 걸었다.

## 쓰는 순서

```
모듈 테스터 → 이사노트 담기 → 이사노트 생성 모듈 담기
  → 링크 추가 (이사용/청소용, 정보성이면 건너뜀)
  → 지식iN·카페에서 질문 가져오기 → 고르기
  → 실행
  → 미리보기에서 확인 (필요하면 본문 고치기)
  → 발행대기글로 저장 또는 즉시 발행
```

## 남은 것

- 옛 형식 버튼 3편 — 송림동→주안동, 입주청소, 15평→32평이
  `<a class="button">` 을 쓴다. 나머지는 `div.button-link`
- 웹 검색 기반 근거 수집 — 지금 참조는 네이버 검색 API 만 쓴다.
  수작업으로 찾던 법령·업계 자료와는 범위가 다르다
- CPA 오퍼 링크 — 오퍼 2건의 주소가 비어 있다. 홍보 링크와 이어붙일
  때 필요하다
