## 1. 배경 (사용자 진술 + 실측)

- blogauto 이전 **수작업 운영 시절에도** 노출이 안 됐다 → 대량 발행만이 원인은 아니다.
- 서치콘솔·네이버 웹마스터에 등록하고 사이트맵까지 연동했으나 대다수 블로그가 수집되지 않음.
- `doooit082.com` 계열 중 **메인 도메인만 일부 노출**, 서브도메인들은 노출 안 됨.
- 같은 시기 티스토리는 잘 노출됐다(현재는 운영 배제).
- 예전에 IndexNow를 썼으나 갱신 과정에서 수집이 안 되는 듯해 **제거**, 현재는 색인 도구 없음.

## 2. 실측 점검 결과 (2026-08-22, 운영 블로그 직접 조회)

### 2.1 정상 — 원인이 아님
| 항목 | 결과 |
|---|---|
| robots.txt | 크롤링 전면 허용, 사이트맵 명시 (Yoast 생성) |
| noindex 메타 | 없음 |
| canonical | 정상 |
| title / meta description | 정상 (Yoast가 채움) |
| 블로거 사이트맵 | 당일 발행분까지 반영 |
| blogs.seo_config | 워드프레스 5곳 `auto_seo_enabled=true`, 4곳 `seo_write_capable=true(rest)` |

→ **"검색엔진을 막고 있다"는 유형의 문제는 아니다.**

### 2.2 문제로 확인된 것

**(a) 워드프레스 사이트맵이 최신 글을 담지 못한다**
`doooit082.com` 사이트맵에 **5089번(8/20)까지만** 존재, 8/22 발행한 5092번 없음.
사이트맵 인덱스 `lastmod`도 2026-08-20에 멈춤 → Yoast 캐시 갱신 지연으로 보인다.
구글이 2023년 sitemap ping을 폐지한 뒤 **lastmod를 크롤 스케줄 신호로 쓰기 때문에**,
사이트맵이 늦으면 발견도 늦는다.

**(b) URL에 키워드가 없다**
- 워드프레스: `doooit082.com/5092/` — 사이트맵 전체가 숫자다 → **퍼머링크 구조가 글번호 기반**.
  blogauto는 이미 `slug`를 전송하고 있으나(`wordpress_publisher.py`, `seo_meta_builder`),
  퍼머링크 구조가 `/%post_id%/`면 slug가 URL에 반영되지 않는다. **워드프레스 설정 문제**.
- 블로거: `blog-post_40.html` — 한글 제목이라 슬러그 생성 실패 시 붙는 자동 이름.
  Blogger API v3는 permalink 지정 필드가 없다(공식). 알려진 우회: 영문 제목으로 생성 →
  제목만 한글로 수정(2단계).

**(c) 색인 알림 수단이 전무**
발행 후 검색엔진에 알리는 코드가 하나도 없다(IndexNow/사이트맵 ping/기타 전무).

**(d) 같은 제목이 여러 블로그에 중복 — 639건** (최대 10개 블로그)
`doooit082.com` 계열 4개는 **같은 도메인**이라 특히 불리.

**(e) 서브도메인 구조**
구글은 서브도메인을 **별개 사이트로 취급**해 신뢰도를 각자 쌓아야 하고 색인이 느리다.
"메인 도메인만 노출됐다"는 사용자 경험과 정확히 일치한다.

## 3. 검색엔진 정책 조사 (2026-08 기준)

### 3.1 구글
- **sitemap ping 폐지(2023-06 공지, 6개월 뒤 종료)**. 지금은 robots.txt + Search Console 제출,
  그리고 **sitemap `lastmod`가 크롤 스케줄 신호**.
- **IndexNow 미지원**(2021년부터 테스트했으나 채택 안 함).
- **Indexing API는 JobPosting / BroadcastEvent 전용**. 일반 글에 쓰면 정책 위반이며
  **권한 회수 대상**(2023년부터 스팸 탐지 적용). → **우리는 쓸 수 없다.**
- **scaled content abuse**: "순위 조작 목적의 대량 페이지 생성"을 AI/사람/혼합 구분 없이 제재.
  2026-03 코어 업데이트의 주요 타깃이었고, 편집 감독 없는 대량 AI 발행 사이트에서
  트래픽 50~80% 감소 사례가 보고됨. **AI 사용 자체는 위반이 아니며, 사람 승인만 붙였다고
  면제되지도 않는다** — 판단 기준은 "사용자에게 실질 가치가 있는가".

### 3.2 네이버 · 빙 — **IndexNow 지원**
- IndexNow 참여: **Bing, Naver, Yandex, Seznam, Yep**. 한 곳에 제출하면 참여 엔진에 공유된다.
- 네이버는 그 외 서치어드바이저에서 **사이트맵 + RSS 제출**을 병행해야 색인이 빨라진다.
- → 사용자가 겪은 "네이버가 수집을 안 한다"에 **직접 대응 가능한 수단이 존재**하며,
  현재 그 수단(IndexNow)을 제거해 둔 상태다.

### 3.3 정리
| 검색엔진 | 즉시 알림 수단 | blogauto 적용 가능 |
|---|---|---|
| 구글 | 없음(사이트맵 lastmod가 사실상 유일한 신호) | 간접 — 사이트맵 신선도 관리 |
| 네이버 | **IndexNow** + RSS/사이트맵 제출 | ✅ 직접 |
| 빙 | **IndexNow** | ✅ 직접 |

## 4. 대책

### 4.1 blogauto 코드로 해결 가능 (착수 대상)

| # | 항목 | 내용 | 기대 |
|---|---|---|---|
| S1 | **IndexNow 재도입** | 발행 성공 직후 해당 URL 1건 제출. 키 파일 자동 배치 확인, 응답코드·실패 로그 기록, 재시도. 블로그별 on/off | 네이버·빙 수집 개선 |
| S2 | **사이트맵 신선도 점검** | 발행 후 N분 뒤 사이트맵에 URL이 들어갔는지 확인해 로그/알림. 누락 지속 시 경고 | 구글 발견 지연 조기 발견 |
| S3 | **형제 블로그 제목 중복 차단** | 애드센스 계획서 3.5와 동일 항목 | 중복 콘텐츠 위험 감소 |
| S4 | **발행량·품질 게이트** | GP 애드센스 프리셋(1일 1포) + 정보이득 강화 조합을 승인 전 강제 | scaled content abuse 회피 |
| S5 | **블로거 영문 슬러그(선택)** | 2단계 우회(영문 제목 생성 → 제목 수정)로 `blog-post_N` 회피 | URL 키워드 확보 |
| S6 | **색인 상태 점검 도구** | 발행 URL의 실제 노출 여부를 주기 확인해 블로그별 색인율 표시 | 효과 측정 |

### 4.2 blogauto가 할 수 없는 것 (사용자 조치)
- **워드프레스 퍼머링크 구조**를 `/%postname%/`로 변경 — 다만 **이미 발행된 수천 개 URL이 바뀌어
  기존 색인·링크가 깨진다**. 신규 블로그부터 적용하는 편이 안전.
- **Yoast 사이트맵 캐시 갱신** 설정 점검(2.2-a).
- 네이버 서치어드바이저에 **RSS 추가 제출**(사이트맵만으로는 부족).
- 서브도메인 → 하위 폴더 구조 전환 여부 판단(대공사, 별도 검토).

### 4.3 효과를 기대하면 안 되는 것
- 구글 Indexing API 사용 — **정책 위반**이며 권한 회수 위험. 검토 대상에서 제외.
- 구글 sitemap ping — 이미 폐지되어 아무 효과 없음.
- IndexNow로 구글 색인 — 구글은 참여하지 않는다.

## 5. 냉정한 진단

기술적 차단은 없고 메타·robots·canonical은 모두 정상이다. 그런데도 노출이 안 된다면
남는 변수는 **발견 경로(색인 알림·사이트맵 신선도)**와 **콘텐츠·도메인 신뢰도**다.

- 발견 경로는 S1·S2로 개선할 수 있다 — 특히 **네이버는 IndexNow가 직접 수단**이다.
- 그러나 구글에는 즉시 색인시킬 공식 수단이 없다. 구글 쪽은 결국
  **"이 사이트의 글이 색인할 가치가 있는가"** 판단에 달려 있고, 이는 2026-03 이후
  scaled content abuse 기준이 강화되며 더 엄격해졌다.
- 수작업 시절에도 노출이 안 됐다는 점, 같은 시기 티스토리는 잘 됐다는 점은
  **도메인/플랫폼 신뢰도 요인**을 강하게 시사한다. 티스토리는 상위 도메인의 신뢰를
  물려받지만, 신규 워드프레스 도메인과 그 서브도메인은 처음부터 쌓아야 한다.
- 따라서 S1~S6은 **필요조건이지 충분조건이 아니다**. 발견 경로를 고쳐도 콘텐츠 경쟁력이
  없으면 색인은 되고 순위는 안 나올 수 있다. 이 점을 전제로 기대치를 잡아야 한다.

## 6. 진행 순서 (애드센스 자동화 이후)

애드센스 계획서 1~5단계 완료 후 착수. 단 **S3은 애드센스 계획서 3.5와 동일 항목**이므로
그쪽에서 함께 처리한다.

1. S1 IndexNow (가장 직접적 · 네이버/빙)
2. S2 사이트맵 신선도 점검
3. S6 색인 상태 점검 도구 (효과 측정 기반 확보)
4. S4 발행량·품질 게이트 (애드센스 자동화와 연동)
5. S5 블로거 슬러그 (선택 · 효과 대비 리스크 검토 후)

## 7. 리스크
- **IndexNow 과다 제출**: 중복·과빈도 제출은 무시되거나 부정적일 수 있다. 발행 1건당 1회,
  재발행 시에는 실제 내용이 바뀐 경우에만 제출한다(이전 운영 실패의 원인이었을 가능성).
- **URL 변경**: 이미 색인된 URL을 바꾸면 기존 노출을 잃는다. 신규만 적용.
- **블로거 2단계 슬러그**: 게시 후 제목 변경이 되므로 발행 실패·중복 게시 위험. 멱등 처리 필수.
- **효과 측정 부재**: S6 없이 다른 항목만 하면 개선 여부를 알 수 없다. 초기에 배치할 것.

## 9. 구현 결과 (2026-08-25)

S1·S2·S6 배포 완료. 배포 SHA `0d35c2a`, 마이그레이션 `051`, 순서도 `docs/flowcharts/search_visibility.md`.

### 설계상 확정된 제약 — IndexNow 키 파일

공식 문서 확인 결과 키 파일은 **호스트 루트**에 있어야 하고, `keyLocation` 으로
하위 경로를 지정하면 **그 경로 하위 URL 만 제출 가능**하다. 따라서:

| 플랫폼 | 가능 여부 |
|---|---|
| 워드프레스 | 조건부 — 사용자가 루트에 키 파일 1회 업로드 (REST API 로는 불가) |
| 블로거 | **불가** — 루트에 임의 파일을 서빙할 수 없음 |

**이것이 과거 IndexNow 를 제거하게 된 원인일 가능성이 높다.** 그래서 키 검증을
통과한 블로그만 제출하고, 403 응답이 오면 검증 상태를 자동 해제해 반복 실패를 막는다.

### S6 → S1 순서 준수 방법

세 기능을 함께 배포하되 `indexnow_enabled` 기본값을 **false** 로 두었다.
색인율 기준선을 먼저 확보한 뒤 사용자가 켠다.

### 첫 실행에서 확인된 것 — §2.2-(a) 가설은 기각됐다 (2026-08-28 전수 측정)

사이트맵 lastmod 와 blogauto DB 의 마지막 발행일을 대조한 결과 **11개 전부 일치**했다.

| 블로그 | 플랫폼 | 사이트맵 URL | lastmod | 마지막 발행 | 최근 8일 발행 |
|---|---|---|---|---|---|
| 굿팁꿀팁 | wp | 454 | 08-28 | 08-28 | 16 |
| 꿀팁대백과사전 | wp | 503 | 08-28 | 08-28 | 9 |
| 인생꿀팁 | wp | 1050 | 08-28 | 08-27 | 7 |
| 잡학다식 | wp | 317 | 08-27 | 08-28 | 8 |
| 군타 | blogger | 423 | 08-28 | 08-28 | 14 |
| 수작남 | blogger | 340 | 08-24 | 08-24 | 4 |
| **라이프인포** | wp | 638 | 08-20 | 08-20 | 1 |
| **인포노트** | wp | 214 | 08-20 | 08-20 | 2 |
| **머니조아** | blogger | 127 | 08-20 | 08-20 | 1 |

**결론: 사이트맵은 정상이다.** §2.2-(a)가 세운 "Yoast 캐시 갱신 지연" 가설은
현재 데이터로 지지되지 않는다. `doooit082.com` 은 8/20에 멈춰 있었으나 지금은
당일까지 반영돼 있다(1,050건). 사이트맵이 오래된 블로그는 예외 없이
**그날 이후 발행 자체가 없었다.**

→ §4.2의 "Yoast 사이트맵 캐시 점검"은 **우선순위에서 내린다.** 다만 8/22 당시의
관측(발행분 누락)이 일시적 지연이었는지는 이제 S2가 자동으로 추적하므로,
`sitemap_miss_streak` 가 쌓이는 블로그가 나오면 그때 다시 본다.

### 부수적으로 드러난 것 — 발행이 멈춘 블로그 5개

굵게 표시한 5개는 **8일째 발행이 사실상 정지**(0~2건)돼 있다. 검색 노출 이전에
발행 파이프라인 쪽 문제일 수 있다(오토런/스케줄러 락, 재고 소진, 키 오류 등).
검색 노출 개선과 별개로 확인이 필요하다. 참고: [[project_scheduler_lock_stuck]]

## 10. 색인 실측 — "노출이 안 된다"의 실체 (2026-08-28)

S6 연동 직후 URL Inspection + Sitemaps API 로 실제 상태를 확인했다.
**추정이 아니라 구글이 직접 답한 값이다.**

### 10.1 색인 판정 — 두 가지 서로 다른 실패

| 블로그 | 구글의 판정 | 의미 |
|---|---|---|
| 인생꿀팁, 잡학다식 (wp) | **"Google에는 아직 알려지지 않은 URL입니다"** | 구글이 URL 존재 자체를 모른다 → **발견 실패** |
| 군타 (blogger) | **"발견됨 - 현재 색인이 생성되지 않음"** | 구글이 알지만 색인하지 않기로 했다 → **품질 판단** |

인생꿀팁 최근 20건 색인 0건. `lastCrawlTime` 이 전부 `None` — **한 번도 크롤된 적이 없다.**

### 10.2 원인 — 구글이 사이트맵을 다시 읽지 않는다

Sitemaps API 의 `lastDownloaded`(구글이 마지막으로 사이트맵을 받아간 날)와
`submitted`(그때 인식한 URL 수)를 우리 실제 발행 수와 대조한 결과:

| 블로그 | 구글 최종 다운로드 | 구글 인식 URL | 실제 발행 | 누락 |
|---|---|---|---|---|
| **인포노트** | — | **제출된 사이트맵 없음** | 206 | 206 |
| **잡학다식** | **2025-11-25** (9개월 전) | 29 | 313 | **284** |
| **인생꿀팁** | **2026-06-22** (2개월 전) | 850 | 1,037 | **187** |
| **월드인포마스터** | **2026-06-27** | 57 | 151 | 94 |
| **머니조아** | **2026-06-24** | 34 | 127 | 93 |
| 라이프인포 | 2026-08-23 | 636 | 626 | 0 |
| 군타 | 2026-08-27 | 423 | 416 | 0 |
| 수작남 | 2026-08-27 | 340 | 335 | 0 |
| 슈마즈 | 2026-08-27 | 130 | 130 | 0 |

우리 사이트맵은 §9에서 확인했듯 **당일까지 최신이다.** 그런데 구글이 그것을
9개월째 받아가지 않는 블로그가 있다. 사이트맵 생성 문제가 아니라
**구글의 재크롤 자체가 멈춘 것**이다.

> ⚠️ Sitemaps API 의 `indexed` 필드는 전 블로그 0 으로 나오지만, 이 값은
> 오래전 폐기되어 항상 0 이다. 판단 근거로 쓰지 않는다.
> 색인 여부는 URL Inspection 결과만 신뢰한다.

### 10.3 중복·낡은 사이트맵 제출

인생꿀팁·라이프인포·잡학다식은 사이트맵이 **3개씩** 제출돼 있고 그중
`/feed`(2023-09-22 다운로드)와 `sitemap_index.xml`(2025-10-26)처럼 방치된 것이 섞여 있다.
정리 대상.

### 10.4 그래서 무엇을 해야 하는가

| # | 조치 | 대상 | 성격 |
|---|---|---|---|
| 1 | **사이트맵 제출** | 인포노트 | 즉시·확실 |
| 2 | **사이트맵 재제출**(삭제 후 재등록 → 재크롤 트리거) | 잡학다식, 인생꿀팁, 월드인포마스터, 머니조아 | 즉시·유효 |
| 3 | 낡은 사이트맵(`/feed`, 방치된 index) 제출 해제 | 인생꿀팁, 라이프인포, 잡학다식 | 정리 |
| 4 | 속성 등록 | 굿팁꿀팁, 꿀팁대백과사전 | 전제조건 |
| 5 | **품질** — 니치 축소·깊이 | 군타 등 "발견됨-미색인" 군 | 장기 |

**IndexNow 는 이 문제를 풀지 못한다** — 구글은 참여하지 않는다. 1~3번이 구글 쪽 해법이다.

### 10.5 계획서 전제의 정정

§5 "냉정한 진단"은 노출 부진의 원인을 도메인·플랫폼 신뢰도로 추정했다.
실측 결과 **두 층으로 갈린다**:
- **발견 계층**: 구글이 URL을 모른다 → 사이트맵 재제출로 해결 가능(기술적)
- **색인 계층**: 알지만 색인 안 함 → 콘텐츠 품질 문제(전략적, [[monetization_strategy_2026]])

발견 계층을 고치기 전에는 품질 개선의 효과조차 측정할 수 없다. 순서는 1~4 먼저.
