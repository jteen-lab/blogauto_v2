# 플로우–모듈–블로그 연결 정합성 정리 계획서

> 작성 2026-08-21 | 상태: 구현 완료(1~3단계)·배포 진행 | 관련 [[adsense_required_pages_module_plan]]

## 1. 배경 (2026-08-21 사용자 지시)

점검 결과 플로우–모듈–블로그 연결에 다음 구멍이 확인됐다.

1. 프롬프트 모듈에 블로그가 연동돼 있어도 **플로우에서 다른 블로그를 자유롭게 추가**할 수 있다.
   추가된 블로그도 그 모듈로 글이 생성되며, 카테고리 모드 모듈이면 원래 다른 블로그용
   주제가 그대로 적용된다.
2. 플로우 안의 프롬프트 모듈이 2개면 **모듈 × 블로그 전체 조합**으로 실행돼, 각 블로그가
   모듈 수만큼 중복 생성된다.
3. 성장 프로파일은 1개 제한이 있으나 **모듈 추가 API에만** 있고 플로우 생성/수정 경로에는
   없다. 애드센스 필수구성 모듈은 제한이 아예 없다.
4. 같은 프롬프트 모듈을 **여러 플로우에 등록**할 수 있고, 둘 다 오토런이면 이중 동작한다.

## 2. 결정 (사용자 확정)

- 프롬프트/생성 모듈에 블로그가 연동돼 있으면 **플로우 블로그는 그 집합으로 고정**.
  다른 블로그 추가 금지.
- 프롬프트/생성 모듈 2개 이상이면 **각 모듈은 자기 연동 블로그에만** 영향.
- 성장 프로파일·애드센스 필수구성은 **플로우당 1개**.
- 프롬프트/생성 모듈은 **플로우 1곳에만** 등록 가능(이중 동작 원천 차단).

## 3. 설계

### 3.1 모듈의 연동 블로그 판정 (단일 기준)
신규 `app/services/flow/module_blog_scope.py`:
- `resolve_module_blog_ids(module) -> set[int]`
  - `settings.blog_category_map`의 blog_id 우선, 없으면 `settings.blogs`(int/{"id"} 혼용 허용)
  - 프롬프트/생성 타입이 아니거나 연동이 없으면 빈 set = "블로그 한정 없음"
- 프런트(`flows/form.js`)의 판정과 동일 규칙 — 서버가 권위, 프런트는 UX용.

### 3.2 플로우 저장 시 검증·정규화 (`flow_service`)
`create_flow`/`update_flow` 공통 적용:
1. **타입별 1개 제한** — `growth_profile`, `contact_form` 각 2개 이상이면 400.
2. **프롬프트/생성 모듈 단일 플로우 점유** — 다른 플로우에 이미 연결돼 있으면 400
   (자기 자신 플로우는 제외). 어느 플로우인지 메시지에 표기.
3. **블로그 범위 강제** — 선택 모듈들의 연동 블로그 합집합이 비어 있지 않으면
   `blog_ids`를 그 합집합으로 **교체**(초과분 무시). 합집합이 비면(카테고리 모드 전용)
   사용자가 고른 블로그를 그대로 둔다.

### 3.3 실행부 — 모듈별 블로그 분리
- `flow_scheduler._execute_generate_module`: `for prompt_module: for blog in blogs` 를
  `blogs_for(module)` 로 좁힌다. 연동이 없는 모듈만 전체 블로그 대상.
- `flows_execute.execute_single_module`(prompt/generate): 지목된 모듈의 연동 블로그로 한정.
- 하루 한도 검사가 블로그 1개 초과로 **플로우 전체를 중단**하던 것도 함께 수정
  (해당 블로그만 건너뛴다).

### 3.4 UI (`flows/form.js`, `_blog_select_card.html`)
- 선택된 프롬프트/생성 모듈에 연동 블로그가 있으면 **비연동 블로그 체크박스 비활성화**
  + "이 모듈에 연동된 블로그만 사용합니다" 안내.
- 이미 다른 플로우에 등록된 프롬프트/생성 모듈은 **선택 불가**로 표시(어느 플로우인지 노출).
- 성장 프로파일·필수구성 탭은 **1개 초과 선택 시 즉시 경고**(저장 전 차단).

## 4. 단계
1. ✅ 판정 헬퍼 + 플로우 저장 검증/정규화 (073c06b, bdc17c0)
2. ✅ 실행부 모듈별 블로그 분리 + 하루 한도 부분 스킵 (c7c0463)
3. ✅ UI 잠금·경고 — 사용처는 별도 API 없이 플로우 목록에서 계산 (2d660ec)
4. ✅ 로컬 검증: 임시 DB로 9개 규칙 시나리오 통과
   (연동 밖 블로그 제외 / 모듈 이중 등록 차단 / GP·필수구성 1개 제한 /
    연동 블로그 자동 연결 / 카테고리 모드 사용자 선택 유지 / 자기 플로우
    재저장 허용 / 수정 시 이중 등록 차단 / 블로그만 수정해도 범위 강제)

### 구현 시 계획과 달라진 점
- 모듈 사용처 조회용 API를 새로 만들지 않고, 화면이 이미 불러오는 플로우 목록에서
  계산한다(요청 수 증가 없음).
- 하루 한도는 블로그별 성장 단계의 daily_count를 우선 적용하도록 함께 정확화.
  (기존에는 첫 매칭 단계 값을 모든 블로그에 일괄 적용)

## 5. 리스크
- 기존 데이터: 현재 11개 플로우가 모두 `프롬프트1 + 블로그1`이라 신규 규칙 위반 없음
  (조회로 확인). 블로그 중복 연결·모듈 중복 등록 사례도 0건.
- 블로그 범위 강제는 **사용자가 고른 블로그를 서버가 조용히 바꾸는** 동작이므로,
  응답/로그에 무엇이 제외됐는지 남긴다.
- 카테고리 모드 모듈은 연동 블로그가 없어 기존과 동일하게 동작(하위호환).
